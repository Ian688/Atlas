## 1. 你的任务与最终目标

你负责持续实现 Modus Code Atlas：一个以本地代码事实为底座、支持代码架构拆解、交互式 Review、真实数据 IO 造影、代码解释和受验证 AI Coding 的产品功能。

## 3. 不要再次走偏的核心共识

### 3.1 Rust 是已确定的核心实现路线

Atlas 本地核心用 **Rust stable 工具链、2024 edition** 开发，承担文件扫描、内容身份、快照、分区作业、事实入库、邻接索引、图查询、增量发布与资源控制。不要重新讨论“要不要 Rust”，也不要交付一个把全部核心工作转交旧 Python 后端的 Rust 启动壳。

核心之外的分工：

| 部分 | 主方案 | 开发要求 |
|---|---|---|
| Modus 宿主 | CPython 3.14 标准构建 | 升级声明、依赖、CI、打包与实际运行；会话、Agent、预算与产品服务接入 |
| 桌面与画布 | 受支持 Electron 稳定版、TypeScript、布局 worker | 升级必要 API，保证真实预览、窗口、IPC、退出与离线分发 |
| JS/TS 语言 worker | 独立 Node.js 24 LTS、固定 TypeScript 分析器 | 复用成熟解析 / 类型能力；独立于 Electron 内嵌 Node |
| Python 语言 worker | 独立 CPython 3.14 与适配器 | 静态语义分析和探针准备，按目标项目解释器声明采集能力 |
| 用户项目执行 | EnvironmentManager + ScenarioRunner | 原环境、升级候选、依赖制品、测试与差分证据分别绑定 |

以上是目标组合，未经过本仓库迁移验收。UP-00 固定具体补丁、工具链、分析器、包锁和分发制品；采用官方资料核对版本与 API，记录实际安装和兼容性结果。普通 crate / 存储 / IPC 选型可自主决定；更换用户确认的核心路线需要新的产品决策，不能用“简化实现”作为自行改回全 Python 的理由。

### 3.2 本地事实不消耗产品 LLM token

导入、文件清点、L0/L1/L2、受支持的 L3 分析、关系查询、布局渲染、测试、trace 回放、基础约束和事实报告全由本地程序与算法执行。模型关闭、未配置或不可达时这些功能仍应按声明能力可用。

LLM 只参与按需解释、复杂意图和 AI 修改；上下文由本地事实、影响关系、源码片段及报告编译形成，具有范围、来源、预算和省略说明。不要把逐文件询问模型、云 embedding 或上传全仓作为索引的必经路径。

本地零模型验收针对的是**产品运行期间的模型调用**；作为开发者的 Coding Agent 自身使用模型完成开发不属于这个指标。通过真实 provider 调度边界计数和阻断模型请求验证，不能仅断言某个新组件没有调用 SDK。

100% 本地解析是本任务重中之重。核心算法不能遇到复杂内容就调用模型，也不能把所有关系标 unknown 来绕过已声明支持的规则。语法树、作用域绑定、CFG、局部值 / 别名传播、调用目标、匹配返回、递归摘要与增量撤回按算法规格真实实现；证明本地链路和语义结果后，UI 再声明相应 Review 能力。

### 3.3 UI 必须保持已确认的形体与交互

- 文件夹是嵌套的**平面方形 / 矩形分隔框**，不画成立方体。
- 文件是大小不同的玻璃圆柱；函数对象位于所属文件柱内，以切面、抽屉或分层表示。尺寸按明确规则随对象数量变化。
- 管道连接函数层和端口，区分文件内、文件间、目录间联系；检查列表是辅助入口，不能把所有函数再次拆离文件柱。
- 执行事件驱动真实激活与数据颜色、函数名 / 输入 / 判断 / 输出的柱外提示。手动选择只改变检查状态，不伪造执行。
- 运行完成、失败、取消或等待后留存已经过的线路与函数层，其余区域灰色静默。修改输入草稿、展开抽屉、查看灰色对象不清空本次路线；实际开始新运行才创建新路径记录。
- 全貌与局部同时可定位；聚合必须能查看成员与数量。大项目不创建百万 DOM / GPU 对象来假装“完整”。
- 模块自动抬升已获准暂缓。不得因它未做而阻塞首个闭环，也不要因此省略事件驱动的激活与线路留存。

### 3.4 证据不能互相冒充

调用图、数据派生 / 传递、控制依赖、静态可能路径、规则模拟与本次真实运行分别表达。`compute` 先调用 `tokenize`、再将结果传给 `parse`，不代表 `tokenize` 调用了 `parse`。

无法解析的动态调用仍保留源位置、候选或未知原因，不隐藏，也不让 LLM 补成 resolved。运行事件与报告绑定源码快照、构建、环境与采集器；模型解释不能变成事实或权威验证回执。

### 3.5 用户项目的升级是可比较的迁移

保留原环境，另建升级候选，比较同一任务的输出、异常、IO、副作用、覆盖和性能。区分仅升级运行时、同时升级依赖、需要源码迁移三类变化；新环境采集事件更多不自动代表行为变化。Python 3.11 目标不会因为 worker 使用 3.14 就拥有目标解释器中不存在的 `sys.monitoring`。

环境安装和构建属于执行，不混入只读索引。简单准备与差分报告在本地完成；复杂修复按需交给 LLM。原环境不可运行时如实报告证据缺口，候选通过测试不能证明与未知基线等价。

### 3.6 函数级测试与多选是底层合同

每个已识别函数可作为 Review / 测试 / AI 修改目标，但能否直接调用取决于上下文。实现本地 FunctionExecutionProfile 与 ExecutionContextPlan（主设计 16.11–13、算法 AL-16），提供直接调用、fixture / 工厂准备、上游场景触发及明确缺项。保持 this / self、闭包、初始化、异步与清理语义；不要复制函数体 eval，不用 LLM 猜运行时状态，不把公开导出自动当作无副作用的纯函数。

选区、实际入口、依赖包络、观测与写范围分别保存。所选函数可依赖未选中的真实函数；多选支持分别测试、真实关联场景、显式试验接线，人工接线不能冒充项目原有关系。无模型时完成 profile → prepare → run → 事实 / 断言报告。

复制测试至少区分序列化输出、向替身发送的内容和真实资源的独立读回。返回成功 / 退出码 0 / UI 提示均不能替代效果断言；没有预期或缺少探针时显示探索结果 / 不确定。模型按需得到必要源码、依赖、上下文、替身模式与运行证据，不能因为选了一个函数就省略相关契约，也不能自动扩大源码写范围。

### 3.7 自然语言场景与画布新增功能

用户可以描述外卖 APP 的查券、领券、下单、用券、支付等业务步骤；LLM 经本地证据绑定操作、提出 ScenarioPlan，Atlas 校验 / 准备 / 执行，实际事件驱动玻璃管道。模型可通过 ViewCommand 聚焦、解释和预演，但不能直接制造调用事件或通过状态。缺失业务功能形成 missing_operation / DesignIntent，不是假执行。

画布新增功能先进入独立 IntentGraph，生成候选源码后由本地解析发布 CodeGraph，再通过真实测试形成 RunOverlay。部分生成、语法错误、占位到多实体映射、未接入入口和并发冲突都要可见。单个新函数存在不等于 APP 功能可用；验收必须覆盖真实接入、相关旧行为和独立预期。工具、身份和状态机按成熟规格实施。

### 3.8 同一核心服务 Modus 与外部 Agent

Atlas 拥有独立解析、执行 / Review、上下文编译、候选变更验证与通用工作台状态，Modus 和外部宿主通过适配器使用。必须做成无 Modus server / 私有会话表、无模型也能执行的独立链；先在当前仓库按依赖方向实施，不要求立即另建仓库。

实现 WorkbenchState、SelectionEnvelope、冻结 InteractionRequest、本地邮箱、版本 / 租约 / ACK 和有界读取。通用 MCP / CLI 可以完成选区 → 报告 → 测试 → 改动；宿主不支持消息推送时提供显式请求引用 / pull。WebMCP、MCP Apps 和 App Server 是不同接入面；不凭概念宣称当前 Codex Desktop 支持，也不使用私有聊天注入。适用 HI-01–16 纳入 MX 与 MT 的证据，未支持的增强明确声明。

### 3.9 正式 2D / 3D 双视图

实现一个事实底座上的两个正式工作视图。3D 展示结构空间，2D 按结构 / 调用 / 数据 / 运行 / 变更生成本地有界投影；同一选区、标注、快照、运行游标和留痕可往返及对照。聚合与路径摘要必须保留成员和来源，递归、共享依赖、并发、未知不能被简化成虚构单根树或直接调用。

ProjectionSpec / ViewProjection、canonical 与 display instance、Agent view_command 的模式 / 镜头字段从 CA-00 / AL-12 接入。2D 支持相同测试、标注、IntentGraph 与 AI 变更验证；拖动节点不改源码。按双视图规格 DV-01–16 验证，不为新增 UI 重做一个解析器、模型建图器或独立聊天机制。

CA 与 UP 会联合推进：UP-02 负责独立服务 / worker 的运行与分发，CA-01–04 负责其实际索引能力。不要把这两者互相等待成循环依赖，也不要为了“完成 UP-02”只做空服务。

同时遵循引擎门 GE-0–3：基础链通过 GE-0 后可以接 UI；正式 R0 语义 Review 要通过 GE-1 的适用 CFG / def-use / 调用摘要用例。R1/R2 按发布语言与运行 / 增量范围通过 GE-2，R3 通过 GE-3。CA-16 扩展深分析，不能等到它才开始写最基本的数据流算法。UI 或 AST 库自带测试不能代替这些门。

UP-00 / CA-00 先完成必要实验、协议与材料，随后立即进入真实链路。不要连续多个开发周期只重写计划、列目录或创建空接口。第一条链必须使用一个未出现在 demo 中的项目结构 / 语法变体，包含至少一个明确未知项和一个可追溯关系，验证解析不是硬编码。

首发语言是 JS/TS，Python 随后达到同等产品闭环。**核心用 Rust 不等于已经支持解析任意 Rust 项目。** Go、Rust、Java、C/C++、XL、字段级血缘等按主设计的扩展工作包另行取得资格；保持架构可扩展，不虚报支持范围，也不以这些扩展无限推迟 R0–R3。

MX 可沿依赖穿插基础阶段，不必等 R3 后才定义接口。新增成熟首批生态与门槛按成熟规格第 3、12 节在实施前固定，用真实项目取得资格；不能临近交付才把全部困难任务改成“不支持”。

## 7. 持续工作的节奏与停止条件

每轮按以下闭环执行：读取当前断点 → 确定一个依赖满足的真实切片 → 实现 → 检查实际 diff → 运行针对性验证 → 修复 → 写入证据与进度 → 进入下一切片。

用户中途问进度或补充细节时，先简要回应并更新约束，再继续原目标；除非用户明确要求停止或替换任务。保持简短、有效的进度更新，说明已取得的事实、正在解决的问题和下一步；不要刷屏输出无变化的轮询。

常规本地代码修改、依赖实验、构建和测试按现有任务授权推进。模型调用、数据上传、外部服务写入和发布遵守实际授权范围；不要为了省事关闭既有预算、权限或数据披露边界。缺少某项外部授权时，继续本地可验证工作，不把不可执行的实测伪装为通过。

仅在以下情形结束当前执行：总范围已按合同完成；用户要求停止；平台会话 / 工具达到硬限制；或者所有当前可推进路径都依赖真实外部阻塞。最后两种情形必须先保存可恢复断点并明确未完成项，不能标成整体完成。一次工具异常、一个失败测试、缺少某个语言包、完成一个阶段或“任务很大”都不是自动放弃其余工作的理由。

不要无限重试相同错误。记录症状与原因假设，改变一个关键条件后验证；确认是缺凭据、设备、系统能力或重叠工作树等外部问题时保存解锁条件，继续独立工作。性能差、协议不通、测试挂起通常是应修复的实现问题，不能通过删测试或降低合同解决。

## 9. 验证规则：实际边界、真实结果、可复验

第一条索引链和每个后续切片都要求真实生产入口：Rust 服务、worker、存储、客户端和预览不得各自跑一个互不相连的示例。检查调用路径与状态副作用，不能只凭源码里出现某个字符串、函数名或测试数量作结论。

重点反例必须覆盖：

- 零模型导入与操作，未知 / 损坏 / 排除文件，Unicode / CRLF / 同名 / 嵌套函数，DI / UMD 替换实现。
- 调用和数据传递不同、变更后增量与干净全量一致、崩溃后旧发布版本可读、跨项目 ID / cursor 不泄漏。
- APP 与局部入口真实运行；参数原样抵达目标；异常传播、捕获、等待、取消、重试与清理；回放不重做 IO。
- 函数上下文构造、私有函数上游触发、模块初始化与清理；替身 / 真实复制、独立读回、缺断言 / 缺探针、未触达目标；多选与人工接线、读写范围不同、计划过期。
- getter / proxy / repr 副作用、async / generator / finally / 短路语义、乱序 / 重复 / 缺失事件、source map 与快照不匹配。
- 选灰色对象不伪造运行，留痕不被草稿清空，重新打开 / detach / dock 不重复启动作业，密集目录仍能检查完整成员。
- LLM 迟到 / 失败 / 预算耗尽不破坏本地功能；注释与日志中的指令不改变工具策略；修改与验证绑定实际产物。
- 宿主 / worker / 用户项目的版本分离，原 / 新环境差分、旧环境不可用、安装中断、依赖变化、迁移后并发冲突。

产品 ID 与通过条件以设计第 24 节的 47 个案例为准，算法验收同时覆盖规格中的 52 个 ET 用例和对应 profile；两组有覆盖关联，分别统计。自行新增发现的问题与测试，并保留原 ID 的覆盖。新增测试应捕获真实合同风险，不为低影响文本改动或镜像实现逻辑堆砌测试。

成熟验收增加 MT-01–24 任务族及其实际变体，重点覆盖红包并发 / 幂等 / 支付异常、LLM 误绑 / 错版控制、占位与真实源码区分、部分生成、多文件接入、测试弱化和错误成功。它们与已有产品 / ET 用例交叉映射，不通过数量相加声称功能完整。

### 命令与现有测试通道

开始时核对命令是否实际存在。当前仓库提供 `make test-fast`、`make test-serial`、`make test-integration`、`make test-e2e`、`make test-electron`、`make lint` 等入口；它们的精确行为以当前 Makefile 为准。`make test-electron` 的名称不意味着它已经覆盖真实桌面全部路径，应检查脚本并补齐实际 Electron 运行证据。

实现后的 Atlas 验证入口至少包含：

```sh
cargo test --manifest-path code-atlas/engine/Cargo.toml --locked
.venv/bin/python -m pytest tests/code_atlas -q
.venv/bin/python -m pytest e2e/test_code_atlas.py -q
npm --prefix electron run test:code-atlas-worker
npm --prefix electron run test:code-atlas-renderer
git diff --check
```

以上 Atlas 模块 / npm 脚本是待创建的合同，未创建或没有执行不能标通过。`.venv` 必须是当前验证工作区使用的目标解释器；先记录实际版本，不能沿用其他 Agent 的旧环境。Cargo.lock、Python 锁、npm 锁、Electron 包和离线制品均与本次评估绑定。

先跑针对性单元 / 合同与实际边界，再按影响范围跑集成、UI、生命周期和回归。宿主升级、协议变更及广泛接缝改造需相应扩大验证。一次通过后，只有代码 / 环境变化、新失败或未解决疑点才重复；不能每一小步都无差别跑全部测试。

挂起先检查资源所有权、任务取消和进程回收。测试与整个命令均有明确 deadline；超时记录为失败 / 超时，不当作 exit 0。不得用删除断言、全局加大 timeout、海量 retry、全部改 serial 或宽泛 xfail 掩盖。fail-then-pass 保留 flaky 记录和原失败证据。

UI / E2E runner 自己管理后端启动、动态端口、readiness、进程与日志清理，不要求开发者手工保持某个固定端口在线。真实 provider、重型 benchmark 和大仓库下载不进入默认测试通道。

### 日志与原有失败

每条命令记录工作目录、结构化 argv 或完整脚本附件、开始 / 结束时间、耗时、真实 exit code、timeout / signal、stdout / stderr 路径和 hash。命令经过管道时保留执行进程的失败状态，不拿最后一条打印命令的 exit 0 代替测试结果。

遇到已有失败，在匹配的起始快照与环境复现后分类：原有问题、本任务回归、环境缺失或原因未知。不要只引用旧文档说“这本来就失败”。本任务导致的失败必须修复；原有问题如果阻碍本任务核心能力，也需解决或明确阻塞对应资格，不能列入 KNOWN_GAP 后照常发布。

`git diff --check` 对未跟踪新文件覆盖不足；新文件还要显式检查，或在仅暂存自己文件后检查 staged diff。格式检查也不能代替功能验收。

## 10. 大项目、效果与发布资格

本地解析能力按设计 L0–L4 分层；规模 S / M / L / XL 与能力层级是两个维度。使用固定语料、构建变体、真实项目和独立的合成压力图，报告正确性和未知比例，再报告速度。不能靠漏解析或隐藏未知获得低延迟。

R3 必须完成设计第 22 节的 L 档验证：约 10 万文件 / 100 万符号 / 500 万关系的压力合同、真实仓库样本、分区与局部查询、质量抽样、内存 / 磁盘 / 恢复，以及有可见预算的大图和大 trace UI。具体时间、资源与抽样目标直接引用设计，不私自改低。

MR 另按成熟规格第 12 节冻结并测试真实任务、生态覆盖、Review 精度 / 召回、场景 / Coding 成功与测试判别能力。新增数值是待校准产品门槛，不是当前成绩；固定语料后保留所有适用失败 / 缺项，不能只选择成功样例。不得用“可以解释 / 可以输出计划”替代场景真的执行、补丁真的接入和独立验证。

默认单元测试避免机器时间抖动；发布资格在固定设备、固定语料和环境下检查绝对预算。设备不可用时可完成实现与其他验证，保留该资格 BLOCKED；不能用一台机器上的相对加速替代要求的资格证据。记录前后耗时、分位数、峰值资源、冷 / 热条件、失败与分母。

LLM 效果按同任务、同模型 / 预算、同基线、同验证器比较文件工具基线、本地符号地图、图 + 运行报告，报告成功率与总 token。不能仅展示第一次上下文更短。没有已授权可用模型时，完成适配和本地受控测试，真实效果仍列未验证；不得伪造模型调用、参与者研究或性能数字。

独立复核必须能够从产物快照与证据包重跑代表性路径、检查 diff 和边界状态。自己的测试通过可以记实现已验证，但 `independent_review` 保持 PENDING，直到实际复核证据到位。复核发现问题后修复并使相关证据失效，重新验证。

Modus 的 `--check`、阶段运行、完整发布裁定分开：结构检查不是执行测试，`STAGES_PASS` 不是 `RELEASE_PASS`，缺失质量 / 安全 / 实际版本证据不能闭合。阶段资格、实现状态、单项验收结果和独立复核状态分别表达。
