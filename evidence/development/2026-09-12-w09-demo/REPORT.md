# 打开就能玩的 Atlas demo（自带示例代码）

窗口：`2026-09-12/w09-demo`
结论：**DELIVERED**。这一轮不交后端进度，交一个**一条命令就能打开、自带示例、能自己点**的 demo。

## 1. 交付

**一条命令**（`scripts/demo.sh`）：

```bash
cargo build
./scripts/demo.sh
```

它做四件事：索引随仓库附带的演示项目 → 起本地服务（**端口由系统选**）→ 从会话文件读回真实地址与令牌 →
打印**可以直接粘贴、已带令牌的地址**（令牌仍只存在于本地会话文件、仍只经 URL fragment 传递，fragment 不进 HTTP 请求）。

**自带的示例项目** `examples/tour/`（4 个文件、12 个函数），每个文件都为演示一件事而写：

| 文件 | 演示 |
|---|---|
| `src/coupon.js` | 真实调用链 `redeem → validate → ledger.write`；`for...of` 循环（元素与累加值都是未知） |
| `src/ledger.js` | 有副作用的函数（校验并可能抛出）+ 一个**可独立运行**的纯函数 |
| `src/dispatch.js` | **解析不出来的调用**：`handlers[type](order)`，Atlas 说"未解析"而不猜 |
| `src/entry.js` | 入口，把上面串成一条可追踪的链 |

**页面上的「试这五步」**（每步一次真实查询，写着它演示什么）：

1. 这个项目里有什么 —— 全量事实（不是本页加载的那一页）
2. 打开 `redeem`：谁调用它、它调用谁 —— 未解析的单独列出
3. 切到「值状态」：这个值从哪来、哪里是未知
4. 它能不能单独跑 —— 静态充分性分类，需要入口驱动的会说明缺什么
5. 哪里是 Atlas 解析不出来的 —— `handlers[type](order)`

并在同一屏写明**现在还不能做的**（受控运行没有主视图、未知清单不能按字节区间高亮、3D 需要 WebGL2），
以免用户以为是自己用错了。

## 3. 这一轮抓到的三个真问题（都修了）

1. **脚本打印了一个已经死掉的地址**：被强杀的旧服务不会清理会话文件，脚本把它当成"这一轮的会话"
   → 现在启动前先清掉遗留会话文件；
2. **端口被上一轮遗留的服务占着**，报错却是"服务没有起起来"，而浏览器 200 其实是**另一个 atlas 实例**在应答——
   这种混淆最伤人 → 现在端口交给系统选，并盯着服务进程，失败就当场打印日志尾部；
3. **给零个未知提供了「查看这 0 处未知 →」按钮** → 未知为 0 时不显示按钮。
