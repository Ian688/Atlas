# Atlas 统一设计：产品、交互与代码智能架构

图解与开发交接见 [Mermaid 开发图谱](design/product-blueprint/README.md)。

2026-09-15 · 统一设计 v2。本文是产品与设计的主文档，合并代码解析架构、Vibe Coding、Review、界面与 Agent 协作讨论。说明用户任务、页面动作、事实来源和交付路线；不是已实现功能清单。当前执行节点由 [任务书](DAILY_DEVELOPMENT_WORK_ORDER.md) 管理；探索页具体布局继续用 [地图设计](design/atlas-explore-next/DESIGN.md)。

## 1. 产品承诺与第一批用户

**Atlas 帮助开发者看懂陌生项目，指导编程 Agent 修改，并用源码、测试和实际运行判断修改是否符合预期。**

优先服务需要亲自对修改负责的人：接手已有项目的开发者、使用 AI Coding 的个人和小团队、需要检查生成代码的产品开发者。Vibe Coding 用户可以从业务意图和场景进入；专业开发者可以直接查源码、依赖和执行记录。两种入口共用同一份证据。

首个值得交付的完整任务：用户发现价格计算边界错误，从地图定位价格模块，描述“负金额报错，零金额允许”，让 Agent 提交修改，确认失败用例在基线失败、补丁通过，检查调用方与其余测试，然后应用修改。用户离开时能说明改了哪里、为何这样改、验证了什么。

不以功能数量、节点数量、动画复杂度衡量价值。首轮产品验证观察：真实用户能否完成上述任务、哪里需要回编辑器补救、是否误读测试与 AI 判断、是否愿意在下一次修改继续使用。需求与付费意愿尚未经过用户研究，不以设计推导市场成立。

## 2. 可感知的工作台

### 2.1 用任务连接功能

任务入口支持“理解功能、排查问题、实现需求、检查修改”。用户可以从自然语言、代码节点、失败场景或本地变更发起，不必先知道函数名。自然语言定位返回附依据的候选节点，允许用户纠正，模型推测不直接变成确定关系。

任务保存目标、允许范围、相关节点/版本、验收条件、讨论、场景、提案和决策。任务进度与索引/运行作业状态分开：需求已确认不代表测试已通过，Agent 完成不代表用户已接受。

| 任务 | 初始输入 | 用户得到的工作区 |
|---|---|---|
| 理解功能 | 问题或节点 | 候选入口、源码、关系和解释依据 |
| 排查问题 | 实际现象、预期、复现条件 | 失败场景、关联源码与调查记录 |
| 实现需求 | 目标与范围 | 可编辑验收卡、上下文、Agent 提案 |
| 检查修改 | 提案或后续接入的本地 Git 变更 | 差异、影响、验证结果与审阅意见 |

Vibe Coding 的需求卡把“加一个导出按钮”拆成出现位置/使用者、数据/格式、空态/失败/等待、成功判据。按任务需要逐步补充，不强制用户填写全部字段。确认后的条目可以转为场景；Agent 生成的候选断言仍需依据用户意图确认。

### 2.2 页面与工作区

顶部始终保留项目、当前源码版本、全项目搜索、当前任务与后台作业。主导航为探索、验证、审阅；Agent 讨论属于当前任务，可从任何页打开。项目设置和 3D 保留入口，不需要用户为完成同一任务反复寻找孤立页面。现有导航可逐步调整，不要求先重写整个应用。

```text
项目 / 版本     搜索文件、函数、文本      当前任务：修复金额边界      后台任务
────────────────────────────────────────────────────────────────────
工作区列表 │ 项目地图 / 调用关系 │ 源码 / 差异 / 场景 │ 对象详情 / 任务讨论
关注节点   │ 每区独立标签       │ 每区独立标签       │ 简介 · 依据 · 批注
────────────────────────────────────────────────────────────────────
可展开的验证区：场景列表 │ 结果、断言、日志 │ 实际轨迹（有采集时）
```

默认只打开地图和详情，不把所有区域挤满。选中节点后，主动作随类型改变；源码、对照与结果按需在旁边打开。区域可最大化、关闭和恢复，窄屏用单区与抽屉。旧页入口继续可用。

代码树是语义对象的入口。文件树表示包含关系，调用图表示调用，数据来源图表示值的推导，运行图表示某一次观测。用户切换“结构 / 调用 / 数据 / 本次运行 / 本次修改”视角；每个视角有自己的图例和适用范围，不把所有边混在一张图里。

节点可显示当前任务相关的徽标：已修改、关联失败场景、未处理批注、分析不完整。无可靠映射时不贴“无测试”“安全”等结论。徽标可点开其具体记录，不能只是一种颜色。

### 2.3 按问题切换地图

结构、调用、数据、运行、修改是同一程序的不同投影。地图提供“谁受这次修改影响”“值从哪里来”“哪些场景实际经过这里”“新增/移除了什么关系”“还有什么没解析清楚”等入口。每次打开有范围、有图例的视图，不默认铺满所有边。

相关测试的关联注明静态引用、实际覆盖、用户关联或 Agent 建议。语法层级深不等于跨文件语义理解深；语法树作为按需检查工具，日常默认展示对任务有用的声明和关系。

## 3. 功能设计与交付判断

“已有基础”表示有代码或此前交付证据，不能替代当前包复验。“新设计”表示下面定义了用户行为，仍需开发。“技术验证”表示必须先取得真实数据，才能承诺对应体验。

| 功能 | 用户点什么，得到什么 | 价值与实现判断 |
|---|---|---|
| 项目地图与多区 | 展开目录/文件/成员，搜索任意节点，在旁边打开子树或源码 | 降低接手成本。已有新实现入口，尚未做本轮独立验收 |
| 对象解释与知识 | 点 i，切换算法摘要、原始注释、按需 AI 解释；点依据定位源码；编辑保存自己的解释 | 理解可核对。已有实现入口；跨版本旧解释需提示复核 |
| 调用与引用 | 点“谁用到它 / 它依赖谁”，显示调用点、路径与源码；按需逐层展开 | 判断修改范围。调用已有基础；通用引用/模块依赖需补能力与区分 |
| 值来源与去向 | 选返回值/参数/表达式，点“值从哪里来 / 影响哪里”，显示赋值、条件、参数传递和未知边界 | 定位错误原因。引擎已有局部流分析；任意表达式到跨过程追踪需补查询及界面 |
| 修改影响 | 选提案，地图标出直接修改、静态候选影响、实际受影响场景三组对象；点击看依据路径 | 降低漏改风险。已有图差异；完整影响视图新设计，静态可达不等于行为改变 |
| 场景与断言 | 点“保存为场景”，输入参数/步骤与预期；批量运行，逐项看实际/预期 | 把试跑变成可重复验证。函数运行已有；可复用场景、断言、集合需新增 |
| 项目测试 | 选择项目已有测试命令，运行后展示测试列表、失败断言与源码、日志；无法结构化时显示原始输出 | 利用既有测试资产。命令执行已有；结构化报告与节点映射需适配器 |
| 修改前后验证 | 同一场景分别运行基线和补丁，展示断言与结果差异，固定两边源码版本 | 判断修改是否解决问题。单输入对照已有；场景矩阵需新增 |
| 运行轨迹 | 选一次有采集记录的运行，展开真实调用时间线，点击事件看源码和当时采集的值 | 解释实际发生的行为。当前没有完整调用/行级轨迹，需技术验证后开发 |
| 调试 | 对可调试入口设断点，暂停后查看栈帧/变量，继续或单步，结束后保留会话摘要 | 找到失败根因。新能力；先接一种运行时，调试不等于事后回放 |
| 任务化 AI Coding | 在节点写目标和验收场景，预览上下文后复制/交给配置的 Agent；回复与提案挂回同一任务 | 减少重复解释和改错位置。公开接口已有；端到端任务关联需完善验证 |
| 审阅与采用 | 打开任务/本地变更，先看目的与证据缺口，再看文件差异、影响与场景；批注、要求修改、应用/撤销 | 缩短 AI 代码验收。提案链已有；本地 Git 变更导入和任务级结论新设计 |

优先级依据是完成修改任务的贡献：影响、可重复场景、前后验证、任务审阅优先于更多摘要样式、3D 装饰和泛化聊天。轨迹与调试有价值，但需要专门实现，不能占位宣称可用。

## 4. 不同节点的常用操作

所有节点都有 i、批注、复制定位、新标签、新展示区、在项目中定位。更多菜单按类型组织，主动作放在详情头部；无能力时解释原因并给可用替代入口。

| 对象 | 主动作 | 更多操作 |
|---|---|---|
| 项目 | 搜索入口、查看本次修改、运行项目测试 | 分析状态/重新分析、启动与测试配置、创建任务、切换版本、3D 浏览 |
| 目录/模块 | 打开子地图、查看模块依赖 | 范围内搜索、范围变更、批注交接；只有存在映射的测试才能称“相关测试” |
| 代码文件 | 阅读源码、查看声明与引用 | 文件差异、文件批注、为此文件创建任务、关联场景；不默认把文件当作可执行入口 |
| 类/方法/函数 | 查看调用、准备运行、创建场景 | 值来源/影响、已有失败记录、前后对照、提出修改；类/闭包的运行条件需具体说明 |
| 表达式/变量 | 值来源、使用位置 | 针对源码范围批注、复制上下文、关联到观察事件；不能假装所有符号已受支持 |
| 测试/场景 | 运行、看最近结果 | 重跑失败、基线/补丁对照、进入受支持的调试入口 |
| 文档/配置/其他文件 | 阅读或预览 | 批注、修改审阅、交接；配置不自动执行，二进制仅展示能读取的元信息 |

功能关系从框架或配置中识别时注明“来自规则”；由模型推测时注明“建议关联，待确认”。例如页面组件与后端接口不能只凭名称相似就宣称连通。

### 4.1 让按钮随任务上下文变化

| 上下文 | 优先动作与反馈 |
|---|---|
| 函数 | 看调用者、准备运行、创建场景、提出修改；准备运行先展示必要输入与条件 |
| 失败场景 | 实际/预期、定位源码、重跑、交给 Agent 排查 |
| 提案 | 看差异、验证、前后对照、添加意见 |
| 分析不完整 | 缺失原因、已知部分、调整配置后重试 |
| 运行事件 | 定位源码、已采集的值、关联调用；缺少记录不补动画 |
| 审阅意见 | 查看依据、要求修改、标记处理、记录不采纳原因 |

高频动作放详情头部，低频动作放更多菜单。保留键盘、触摸可达性。加载、空态、失败、取消、过期都给下一步；重试必须针对失败原因，不能无限重复同一请求。

## 5. Review 是对修改作判断

入口同时支持 Atlas 提案与后续的本地 Git 工作区/提交差异。先实现本地导入，远程 PR 同步按实际用户需求再接。

审阅页三栏：左侧为任务与变更文件；中间为差异/影响；右侧为验证与决策。

中间区切换三种视图：源码差异回答“哪些行变了”；结构与接口差异回答“声明、参数、依赖、调用关系变了什么”；行为对照回答“同一场景实际结果变了什么”。后两种只能展示已取得的数据，不能由 diff 摘要推导全部行为。

意见分确定缺陷、可能风险、风格建议；每条包含位置、依据、建议、处理状态，避免大量低价值意见淹没缺陷。新补丁生成后，旧验证与旧审阅意见仍属于旧版本；当前版本显示需重跑/复核，不继承绿色通过。

用户先看到四项：修改目的、涉及文件/对象、已经运行的场景与测试、尚未验证的问题。AI 总结附具体差异引用，不能用总体风险分数代替可检查的问题。

点一项问题：打开对应行与推导路径，显示发现者、依据、建议与处理状态。用户可以批注、要求 Agent 修改、标记解决或记录不采纳原因。新补丁到来后，旧意见按原版本保留，能可靠重定位的再关联到新版本。

“验证通过”与“用户接受”分别记录。应用确认显示实际项目、文件、基线漂移与证据缺口；未跑测试允许用户明知情况下作决定，不能自动显示绿色通过。应用/撤销继续复用现有授权与字节校验。

完成标准：用户能从一条需求走到具体改动和对应断言，发现未覆盖部分，作出采用/返工决定。仅展示 diff 不是完整 Review 设计。

## 6. 测试与运行的区别落实到界面

运行入口分为“函数输入”和“项目命令”；浏览器场景稍后接入。启动配置保存工作目录、命令、环境变量名称、超时与所需权限；秘密值不能进入导出报告。

函数场景包含目标版本、参数/this/必要 globals、预期返回或异常。用户从一次运行保存场景时，系统建议当前结果作为候选预期，要求用户确认业务含义；错误结果不能自动成为正确标准。

场景列表显示名称、预期、最近状态和所用版本；支持单个、选中集合、重跑失败。结果面板首先显示断言差异，再是输入/日志/技术条件。超时、取消、拒绝、未运行独立于失败断言。

基线/补丁矩阵逐场景显示两侧结果。典型修复是目标场景“基线失败→补丁通过”，其他已声明回归场景保持通过；新增失败明确列出。比较使用同一声明环境，外部状态无法固定时显示限制。

项目测试先集成一种已有框架的结构化结果，不重写测试框架。覆盖率必须来自实际报告并校验源文件版本；“执行覆盖到此行”不等于“断言保证此行正确”。没有测试发现或映射能力时不说没有测试。

## 7. 真实轨迹、追踪与调试的技术路线

第一种轨迹场景选择本地 Node 的可复现函数/测试入口，与现有 JS/TS 链相接。产品依然语言中立，逐语言披露文件阅读、符号、数据流、执行、轨迹与调试支持。

先做独立技术验证：固定源码与 sourcemap；选择 Inspector 或定向插桩等采集方式；验证同步嵌套调用、异常、异步任务和 TypeScript 定位。比较采集开销、行为变化和事件缺口，再确定默认机制。CPU 采样不是完整调用记录，普通日志也不能补成完整路径。

首个可交付轨迹显示事件列表与调用树、异常、记录到的参数/返回，点击定位源码。事件要有运行/版本、顺序、事件类型、位置与采集模式；只有有证据时才提供父子调用/异步因果关联。截断必须可见。不要求首轮记录全部变量、堆变化或全局副作用。

暂停调试是一条独立会话：断点 → 启动/连接 → 暂停 → 栈帧/变量 → 单步/继续 → 结束。先选择一种成熟调试适配器或运行时协议接入，复用编辑器中的调试能力也可以交付价值。历史时间线的前后移动只是在看已采集记录，不能标成程序逆向执行。

浏览器流程后续复用 Playwright trace：操作、DOM 快照、网络与控制台可帮助定位界面失败。它不自动得到整个后端的函数轨迹，跨进程因果链需另有采集与关联。

技术参考：[VS Code 调试](https://code.visualstudio.com/docs/debugtest/debugging)、[Playwright Trace Viewer](https://playwright.dev/docs/trace-viewer)。采用现成能力，不把 Atlas 变成自研所有调试器和测试框架的工程。

### 7.1 浏览器行为与源码关联

面向界面开发的首条路线：运行浏览器场景 → 展示步骤/截图/控制台/网络 → 选中失败步骤批注 → 将证据与可靠定位到的源码交给 Agent → 修改后重跑同一场景。

页面元素到组件、事件处理、请求、后端入口的关联需要框架适配、源码映射或运行记录。只知道 DOM 选择器时先保留操作证据；不能凭名称匹配宣称完整前后端链路。每条关联注明来自规则、实际观测、人工确认或待确认建议。浏览器流程接入属于阶段 D。

## 8. AI Coding 协作

“请修改这个节点”生成任务草稿：目标、允许范围、相关节点与版本、用户批注、验收场景。发送前预览实际上下文，默认只选必要源码；补充上下文作为显式动作。

未配置 Agent 时可复制任务包与公开接口信息；已配置时提交真实请求并显示运行/等待/失败/完成。不能把复制文本显示成已发送，不能把模型自报完成显示成验证通过。

返回的解释、建议、补丁和测试结论分别归类，链接具体任务、源码版本及 Atlas 执行记录。用户能看出哪些是 Agent 声明、哪些由 Atlas 实际运行确认。用户也可以在外部编码后导入变更进入相同审阅流程，不强迫换掉现有编辑器。

自动补测试和修复失败是后续协作动作：Agent 先给候选断言，用户或明确的任务规则确认预期，然后运行。Atlas 不以语言流畅度判断修复正确。

### 8.1 Agent 接入与内置 Agent 是两个方向

把 MCP 纳入正式接入设计，与 CLI/HTTP 共用核心查询和执行服务；它是待实现/验证的适配面，现有 HTTP 不能直接称为 MCP。先交本地只读查询工具，再按已有授权规则开放运行、提案与验证。远程部署按真实需求另行设计，不因增加 MCP 默认暴露本地项目。

工具分基础查询与任务查询。基础查询查定义、调用、源码；任务查询组合修改对象、候选影响、相关证据与未覆盖范围。名称与协议以实现时公开合同为准，下表为设计目标：

| 工具任务 | 返回内容 | 不能暗示 |
|---|---|---|
| 定位对象 | 节点、版本、定义范围、匹配依据 | 名称相同就是同一对象 |
| 分析修改影响 | 改动对象、候选路径、依据、范围与未知 | 可达对象一定改变行为 |
| 查关联测试 | 测试引用/覆盖/人工或建议关联、报告版本 | 未找到关联即不存在测试 |
| 比较行为 | 同场景两侧运行、断言与环境差异 | 单次通过即业务正确 |
| 收集交接证据 | 有界源码与记录引用、任务目标 | 默认上传全部仓库 |

调用标识项目和源码版本；结果带来源、覆盖范围、截断与下一页。长任务返回可查询的作业身份并提供适用的取消方式。MCP 适配器不得绕过同一服务的写授权与运行边界。真实 Agent 验收要完成查询→提案→读取验证结果，不以工具注册成功代替。

Atlas 调用外部 Agent 时，使用对方适合会话/任务的接口，不能认为 MCP 自动提供完整聊天、审批、流式差异和会话恢复。内置 Agent 是可选消费者；用户直接查询、运行、审阅无需经过 LLM。是否自建 harness 由实际缺口决定，不作为核心分析前提。

## 9. 技术结构与实施自由

### 9.1 代码智能底座

保留 Rust 服务/分析、SQLite/版本快照、语言 worker、现有提案执行链。当前没有足够依据支持全仓重写。

| 职责 | 生产什么 | 实施判断 |
|---|---|---|
| 文件清点与快照 | 原始字节、内容身份、文件状态 | 复用现有扫描与存储 |
| 语法/语言适配 | 语法结构、声明、作用域、导入、引用、类型材料 | TS worker 已有基础；其他语言选择成熟解析器/编译器接口/索引适配 |
| 语义模型 | 版本内可定位的符号、定义与有类型的关系 | 扩展现有 Symbol/CallSite/Import/Analysis，避免第二套事实库 |
| 程序分析 | 调用候选、控制流、数据来源、跨过程摘要、未知 | 复用已有求解，按用户问题补精度与查询 |
| 修改分析 | 源码变化、变化对象、候选影响、关联测试与记录 | 复用提案/图差异；新增语义与测试映射 |
| 运行观测 | 返回、异常、测试；后续采集轨迹与调试状态 | 与静态分析并列，通过版本与源码位置关联 |
| 证据组织 | 方法、来源、版本、范围、完整性与记录引用 | 组合查询结果，不一定另建引擎或图数据库 |
| 接入与体验 | UI、CLI、API、MCP 与可选 Agent | 共用上述服务，不要求 UI 经过 Agent |

语义关系可逐步包含定义、引用、调用、导入、继承、读写等；接口路由、数据库对象和测试关系需要各自的生产器。支持一种关系才发布一种关系。静态候选、规则推导、观测、人工关联和模型建议保留来源；不使用无依据的总体置信度分数掩盖差异。

节点身份由项目/分析版本和对象定位组成，不能仅用名称；跨版本靠明确重定位，歧义需选择。证据引用固定源码或记录，代码更新不改写历史。

### 9.2 深层探索与局部失败

UI 查询直接成员和所需关系，不因展开节点重新解析全仓，不持有完整 AST。返回真实总数、分页、加载范围与未支持项；包含树没有环，关系图的循环需要去重与有界展开。大图用按需查询、虚拟化和布局控制，不把固定深度当产品边界。

语法错误、语义部分支持、资源预算、查询错误、布局失败分别呈现。可安全发布的局部结果保留可用文件与节点，并明确整体不完整；无法安全发布时保留上一份已发布分析并展示失败原因，不能将不一致结果伪装为成功。

“深层展开失败”尚未在本轮定位根因，不能作为重写依据。用一个最小深层样本分别记录索引、成员查询和渲染结果，确定故障层；再测语法错误文件与正常文件共存、跨文件调用、关系循环及取消，验证已知部分仍可使用。

### 9.3 功能到事实的对应

| 用户问题与操作 | 必需事实 / 生产方式 | 当前入口与需补内容 | 最小验收 |
|---|---|---|---|
| 展开深层节点 | 成员、版本、分页 / 清点与语言解析 | tree/worker/query；核对各层错误与范围 | 深层成员可定位，局部失败可区分 |
| 谁调用此函数 | 调用点与候选目标 / 符号绑定与求解 | CallSite/分析查询已有基础 | 跳回真实调用行，动态未知不漏报 |
| 这个值来自哪里 | 定义使用、条件、参数传递 / 数据流 | flow/inter/query；补用户所选表达式查询 | 已知路径与未知边界可回源码 |
| 修改影响哪里 | 变化对象、候选路径 / 差异与图查询 | patch/图差异已有；补影响投影 | 区分直接修改、候选影响、观测变化 |
| 是否实现需求 | 确认预期、运行结果 / 场景与真实执行 | runner/compare；补场景、断言和矩阵 | 零金额失败→通过，负数/正数回归 |
| 测试是否相关 | 引用、覆盖或人工关联 / 对应适配器 | 测试命令已有；结构化映射待补 | 每项关联可查来源，没有映射如实说明 |
| 本次实际经过哪里 | 采集事件与 source map / runtime collector | 当前完整调用轨迹缺失 | 同步/异常/异步样本及采集缺口可见 |
| 页面按钮为何失败 | 步骤、DOM、日志、网络、源码关联 / 浏览器适配 | 后续新增 | 从失败步骤交接并重跑，无可靠定位不猜 |

### 9.4 实现选择

前端按工作区、图与源码、场景结果、审阅、任务讨论拆组件。多区状态独立，请求携带项目/版本/区域身份。继续原生 JS 或引入类型化组件体系由实施者根据复杂度决定；不为换栈延期已经能交付的用户任务。

统一关联对象是 Project、Analysis、NodeRef、Task、Scenario、Run、Proposal、Review；先扩展现有记录，避免建立第二套相同事实。新场景与结果通过公开接口给人和 Agent 使用。图布局使用成熟库；编辑、diff、测试报告、调试尽量用成熟组件/适配器。

每个新功能在编码前明确：用户动作、可见结果、真实数据来源、缺数据的状态、最小验收任务。精确 schema 随实际适配验证确定，不先制定泛化插件平台。

## 10. 交付顺序

| 阶段 | 可交付结果 | 完成任务 |
|---|---|---|
| A 地图收尾 | 当前 M1–M6，实现与最终包核对；节点到现有运行/审阅可往返 | 陌生项目找到目标，批注并交接，返回同一对象看提案 |
| B 修改验收 | 任务/验收卡、保存场景/断言、集合运行、前后矩阵、任务关联与三种 Review 视图；本地 MCP 复用成熟查询 | 完成金额边界修复，能复跑并解释采用理由 |
| C 定位原因 | 调用/数据来源/影响视图，Node 轨迹技术验证后交付首条真实时间线 | 从失败场景找到源码依据；未采到部分如实显示 |
| D 项目工作流 | 结构化项目测试、本地 Git 变更审阅、浏览器场景与调试适配 | 在一个实际应用上重现、定位、修复、审阅用户流程问题 |

这是一条滚动路线，不是要求同一 Agent 一次完成全部内容。A 中已经做完的工作直接验证，不重新实现；B 优先，C 的技术试验不能阻塞 A 收尾。其他语言按真实试用项目选择下一条接入链，3D 继续保持对象往返并作为范围/影响的可选视图。

阶段 B 按 B1 任务与验收卡 → B2 可复用场景与断言 → B3 场景前后矩阵 → B4 任务级 Review 完成一条修改旅程。MCP 接入成熟查询，不等待全部语义分析或完整轨迹；不得把未来工具空壳当交付。涉及新关系/适配器时，先用最小样本证明确实能生产数据，再扩展界面。M1–M6 的在途实现继续核对与收尾。
