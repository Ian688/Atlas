# 阶段范围与目标架构表述审计

2026-09-15。仅文档修改，无产品代码变更或新增验收资格。

检查当前 AGENTS、统一设计、架构、任务书、产品目标、Agent 启动入口、地图详细提示词/设计、图谱与交接。历史证据不重写。修改前文件保存在 before/。

## 分类与处理

| 原表述或类别 | 判断 | 修改 |
|---|---|---|
| 大仓库资格 deferred（AGENTS） | 阶段验收容易被理解为架构忽略 | 明确索引/按需查询、身份、增量正确性、跨文件、适配层；真实路径缺陷当前修复 |
| 按阶段阅读，不需要一次实现未来架构（四个启动入口） | 缺当前架构责任 | 先落实统一设计第 0 节，再按阶段交付 |
| 不新增语言引擎阻塞地图（地图提示词） | 容易被理解为解析问题可跳过 | 语言中立成员/查询与适配器；当前目标项目解析缺陷贯通修复 |
| 不必结构解析所有配置（地图提示词） | 后续能力缺接入说明 | 当前原文阅读，格式适配器沿同一版本成员接口接入 |
| 不要求首轮全部变量/堆/副作用（统一设计） | 采集交付与数据模型混合 | 首轮采集范围明确，新增采集沿同一运行/源码身份接入 |
| 不在本单自建完整调试器（任务书） | 只有排除项 | 改为按统一身份接入成熟调试适配器 |
| 尚未采集轨迹/未验证平台（能力声明） | 事实状态，非开发禁令 | 保留，不能把未实现改成已支持 |
| 不能伪造观测/越权写入（可信边界） | 必须持续保持的要求 | 保留 |
| 无需完全干净工作树/不必固定布局等 | 实施自由，非产品能力上限 | 保留 |

统一设计新增四类要求和九项目标能力责任表：大仓库、深层语法、跨文件、增量、稳定身份、多语言、Agent/MCP、运行证据、修改影响。没有新增长期产品非目标，也不把“预留”解释为空接口或任意平台。批处理不一概禁止，明确处理单位、峰值、预算、取消和演进路径。

结论：原措辞存在让 Agent 将阶段范围误读为能力上限的风险；本审计没有证据证明它造成了某次解析失败，实际故障仍需复现定位。
