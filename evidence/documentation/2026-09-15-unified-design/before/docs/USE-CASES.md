# Atlas 产品目标与用户任务

更新：2026-09-15。详细产品决策、可见功能、交互与技术路线见 [产品设计](PRODUCT_DESIGN.md)。本文保留稳定用户任务；不是当前能力声明。当前开发顺序见 [执行任务书](DAILY_DEVELOPMENT_WORK_ORDER.md)。

## 交付形态

Atlas 为开发者和 Codex 等编程 Agent 提供本地代码理解、运行验证和修改审阅能力，不限定项目语言。开发者使用可视化工作台，Agent 使用 CLI/HTTP 等公开接口，共用代码版本、提案与验证结果。JS/TS 是当前首条实现链路，更多语言逐步接入。

开发者可以独立安装、打开本地项目、看懂程序、验证行为并审阅修改。用户从项目地图进入具体函数，沿源码和关系理解它，在受控环境运行，再比较修改前后的证据。打开项目、等待/取消分析、恢复上次工作和诊断失败也属于产品。

没有 LLM 时，结构探索、本地分析、受控运行、对照和导出仍有价值。接入 LLM 时，模型解释证据、提出场景与生成补丁；Atlas 将建议绑定到具体代码版本并验证结果。CLI、报告、CI 和 Agent 接口复用同一能力。

## 用户任务

| 任务 | 用户完成的事情 | 可验收的结果 |
|---|---|---|
| 认识项目 | 打开项目、搜索入口、定位模块与函数 | 知道所选对象在哪里，能继续深入；未加载范围可发现 |
| 理解并准备修改函数 | 看调用者/被调用者、值来源、影响与未知，回看源码 | 能沿真实依据判断从哪里改、还缺什么信息 |
| 验证行为 | 配置输入或业务步骤、检查运行条件、执行和查看结果 | 看见实际返回/失败及适用边界，能定位和复现 |
| 审阅与修改 | 提出约束或补丁、隔离验证、看前后差异、应用或撤销 | 修改接入真实入口；知道验证过什么、没验证什么 |
| 交接与自动化 | 保存选区、导出有界证据、让其他工具读取 | 真实 Agent 能通过公开接口完成查询、提出修改、读取验证结果；开发者可审阅同一版本与提案；本地数据不会隐式外传 |

这些任务可分阶段交付，不要求先建完所有算法。阶段内可跨屏、跨模块；必要的底层工作按它解决的用户阻塞衡量。

## 工作空间

- 3D/2.5D 用于结构空间与定位：目录框、文件玻璃柱、函数层、连接对应对象的管道保留既定方向。尺度、材质、渲染库和布局实现可以迭代。
- 2D 用于精确阅读调用、数据、运行和变更关系，布局随问题选择。用户可直接使用任一视图。
- 源码、关系、输入、运行与修改共享选区和版本。切换视图可以继续工作，跨版本对照明确显示两侧版本。
- 静态关系、实际运行和拟议修改分别表达。运行留痕来自采集；导航、加载和状态切换可以使用不冒充执行的动效。

## 设计默认值，而非固定版式

先展示用户的问题与有用结论，技术细节按需展开。优先采用清晰图形、清单和源码联动；不为统一形状牺牲语义。未知有一致的视觉家族，但原因和下一步可区分；多值、部分已知、未初始化等事实保留其实际含义，不硬压成三态。

依据应容易到达，不要求所有源码永久占屏或零点击。关键范围和失败状态可见，其余诊断可折叠。允许并排比较和跨屏任务；不规定每一轮必须改变画面。布局、节点上限、并发数和测试数量是可调整实现参数。

判断产品是否进步：用户是否更容易完成任务，是否误读结论，能否找到依据，以及等待/操作是否可接受。自动化验证实际路径，真实用户反馈校准设计；没有反馈数据就不声称已证实易用。无需为每个小改动建立新的指标体系。
