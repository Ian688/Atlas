# Atlas 前端主设计与渲染方案

版本 1.0 · 2026-09-13。范围：产品工作空间、T1/T2 的页面与交互、3D 结构定位方向、前后端接线。本文让执行者直接实现，不要求重新做一轮产品设计。当前任务顺序仍由 [执行任务书](DAILY_DEVELOPMENT_WORK_ORDER.md) 管理。

## 1. 看什么、做到什么

先打开 [可交互版面](design/workbench-preview.html)，可双击本地文件；源码为 [原型片段](design/workbench-prototype.html)。它演示函数选择、返回、关系/值/未知、源码定位、按参数输入、结果状态、修改审阅和结构定位。**全部关系/画像/结果是标明的设计样例；源码节选来自 examples/tour，不是产品能力或实际执行证据。** 正式实现删除预览条和样例状态选择器，以真实接口数据替换。

设计决定：项目定位留在左侧；当前任务占据中央；源码与依据在旁边。用户不离开所选对象就能从理解走到运行和修改。取消旧页面占据首屏的大标题、重复规模卡片、五步宣传说明与堆叠的功能折叠框；首次引导改为可关闭的轻提示。项目范围、当前版本和失败原因仍有明确位置。

默认首个任务是阅读函数；不是打开软件就强迫用户运行或向模型提问。进入项目先显示可搜索对象与项目结构；有已保存有效选区则直接恢复。

## 2. 页面骨架和空间分配

| 区域 | 默认内容 | 行为 |
|---|---|---|
| 顶栏 | Atlas、项目/切换入口、分析状态、当前版本 | 跨任务稳定；索引中的可用范围与错误可查看，令牌不作为日常输入表单 |
| 左侧项目导航 | 全局函数搜索、按文件分组的结果、返回/最近对象 | 搜索名称与路径，明确匹配范围和分页；不从首页对象推算全库 |
| 对象标题 | 文件面包屑、函数名、返回、主要动作 | 与当前 selection 同步；长名称可完整查看，不挤掉主要动作 |
| 任务页签 | 结构定位 / 理解代码 / 运行验证 / 审阅修改 | 保留选区与草稿；结构页无需经过 3D 才能进 2D |
| 中央任务区 | 关系图、值来源、运行表单或验证报告 | 按任务切换内容，不为每项后端能力加一个永久侧栏 |
| 源码依据区 | 文件/范围、源码、高亮解释、来源/上下文操作 | 图、结论、异常位置可联动；可以收起或扩大，不将运行结果当行覆盖 |
| 底部细状态 | 当前对象/版本、当前范围、局部截断或失败 | 简短；详细诊断按需展开，不重复一排内部指标 |

桌面默认：左栏约 184–208px、源码约 330–360px，其余给任务区。中间图实际可用宽度不足约 520px 时，先将源码移至下方，不把三个面板一起压小。原型在宽度 1080px 以下采用上下排；正式实现可按容器宽度决定。600px 以下导航变搜索+结果列表，任务与源码纵向排列。主目标是桌面，小屏保证能操作和读内容，不追求在手机上塞下完整城市。

正式应用使用工作区高度和各区独立滚动；来源定位只滚动源码区域。源码默认不拆开标识符，长行水平滚动，提供换行开关；扩大阅读保留当前锚点与返回入口。图和源码分隔允许调整宽度，不要求为首片引入通用 docking 系统。原型为便于整页查看采用自然页面高度，不是应用滚动实现。

视觉默认：低饱和灰白/深灰底、青绿色选区、琥珀未知、红色失败。颜色同时配文字/线型；背景少装饰。正文 14px，源码 13px 左右，辅助 12px，图内最低 11px；4/8/12/16/24 的间距阶梯，普通面板不套多层卡片。完整色值与细节参考原型，不必逐像素复制；信息主次和动作位置保持一致。

## 3. 理解代码：默认调用图

首屏选中函数后，三个问题入口是“调用关系 / 值从哪来 / 未知边界”。函数旁显示文件路径，避免同名误选。源码不随悬停改选，点击才形成可返回的导航；悬停只突出关联。

### 3.1 图的显示模型

先构造 `DisplayGraph`，再布局，再渲染；直接复用 `web/layout.js` 的可用能力。

```text
DisplayNode = displayId + entityRef(analysis, entity) + label + path + kind
              + selectionState + provenance + optional membersRef
DisplayEdge = edgeId + sourcePort + targetPort + relationKind + provenance
              + optional callsiteAnchor / membersRef / unknownReason
```

这里是建议的前端模型，不是要求添加新后端公共 schema。布局只接收当前有界子图，不收到整仓 facts。显示 ID 与实体 ID 分开，摘要/同对象多实例不会误写代码。

- 当前函数居中，一跳调用者在左，一跳被调用者在右。无上游写“当前范围未发现已解析调用者”，不声称绝不存在调用。
- 一跳关系从 root 相邻边提取；`reach` 返回的是多跳结果，不能全部贴上“一跳调用者”。下一层用展开或选择新根阅读。
- 已知关系为实线箭头；未知目标为虚线和具名边界节点。参数来源/静态候选/运行实例不用同一种无标签连线混合。
- 每条边有独立端口。端口按相邻节点顺序分配；正交走线保持箭头真实方向，共线路由只有可辨别成员时才做束线。线条交叉不是关系节点。图边可选择并定位 callsite。
- 递归表现为回边或可展开递归组；折叠路径明确“经 N 个对象”，能展开成员，不能画成真实直接调用。
- 未知默认放在所属调用点附近；避免跨越整图的回折虚线。高扇出用“另有 N 个已知对象”和独立未知/截断入口，不堆几百个微型标签。
- 自动布局初次适配视口；用户选中/钉住对象尽量不移动。增加局部邻居只重排受影响区域。缩放文字不能无限缩小，到阈值折叠细节并提供列表。

### 3.2 渲染与线程默认方案

首片继续用 SVG/DOM：节点、标签、端口和边可选择，可测且易与源码联动；图的交互列表同时给键盘入口。布局耗时明显时将现有布局引擎移至 worker，以 selection/query/generation 为任务身份，过期任务丢弃；超时回退可读清单/简单布局。尽早能读源码，不让布局阻塞整个页面。

只在实际可见子图需要时转 Canvas/WebGL，不为了“未来百万节点”提前重建渲染框架。命中索引、文字层和无障碍列表可以复用。静态阅读按需重绘；缩放/拖拽期间请求帧，停止后停止。不把动画当分析/执行证据。

源码、关系、flow、profile 各自加载并局部重试。不要用一个 `Promise.all` 失败把全部面板一起清空。资源状态明确 `loading / ready / empty / partial / error`，保留失败原因，错误不写成零结果。

### 3.3 值来源视图

默认先显示返回值/关键变量的语义行：变量或字段 → 来源摘要 → 条件/不确定性 → 可点源码依据。例如 written 来自初始值或 write 返回值。摘要从真实 `returns`、`def_use`、`block_states` 和 `interprocedural.callsites` 派生，不按示例函数名写业务解释。

点击定义/使用通过 op index 找到 `ops[].start/end`，定位源码；跨函数来源先打开对应对象，再显示具体操作。源字段不存在就写“当前分析未给出此来源”，不猜。块×绑定矩阵作为“详细状态”展开，适合专家比较，不占据第一次阅读的主版面。

### 3.4 未知边界视图

每个条目：影响什么结论、原因、位置、当前能做的下一步。区分未解析调用、未建模操作、预算截断、未采样运行；视觉家族一致，含义不合并。已知部分继续展示，加载失败不伪装成未知事实。没有精确分母时显示已知范围而非百分比。

点击未知位置应真正加载对应源码窗口并高亮；不能仅打开文件头再打印一个很大的字节数。

## 4. 运行验证：完整表单与结果结构

共享当前函数与版本。顶部先给画像：可准备输入、需要上下文、需要入口、当前不支持；使用具体原因，不让用户学习 classification 字符串。

参数按 `params[].index/name` 列出，各项可填 JSON 值；高级模式可编辑位置参数数组，两种编辑器共用同一份草稿。没有类型/默认值证据时不生成推测表单。接入 receiver/具名 globals 后按画像逐项显示，只出现所需输入。闭包路径用真实 enclosing 链预填并允许填写各级实参。

所缺条件分两类：可补充输入与需要明确承认的未知。每项说明影响；不能把不支持的上下文伪装成一个勾选后万能可跑的开关。网络/文件/进程授权仍由现有服务策略管理，不在此表单任意扩大。

| 状态 | 页面表现与动作 |
|---|---|
| 尚未运行 | 输入、画像、目标、运行按钮；无绿色通过标记 |
| 输入错误 | 字段附近说明语法/缺项；保留其他输入 |
| 预检拒绝 | 缺什么、为什么、可操作修正；不显示为函数返回 false |
| 运行中 | 固定本次输入、目标和时间预算；已有输出可显示，禁止重复提交；取消状态按后端能力处理 |
| 返回/抛出 | 返回值或异常、耗时、进程状态、输出；异常有真实锚点才定位 |
| 超时/取消 | 与业务断言失败分开；保留部分输出，明确是否服务端确认终态 |
| 查询/连接失败 | 表示未取得结果；不能推断进程停止，允许重新查询本次请求 |

结果区统一结构：本次目标/源码版本 + verdict + 返回/异常/拒绝原因 + 实际输入 + 输出/耗时/退出状态 + 观测范围。测试预期与函数原始结果分开；函数返回 false 不等于测试失败。历史记录列表保留输入与版本，可重填输入而不自动运行。

当前只采集入口结果；**不在运行后把静态图或多条源码行涂绿**。用户定位用青色边框/底纹并标“源码定位”；真实异常位置用错误色；将来的执行覆盖使用单独图例，等真实采集器存在再接。原型运行按钮只展示状态样例，不启动目标程序。

## 5. 审阅修改：具体报告而非一块 JSON

同一选区打开提案；Intent 有自己的标识。首片支持现有 diff 登记，后续模型生成沿同一提案协议，不新增隐式写入链。

页面由四块顺序组成：

1. **变更说明与源码 diff**：目标文件、基线版本、意图、修改/新增/删除。宽屏并排、窄屏统一 diff；精确锚点可进入源码。
2. **静态变化**：新增/删除/变更对象与关系、匹配方法和不确定性；受影响清单可点。图差异不是行为已经变好的证明。
3. **测试与运行对照**：共同输入、独立预期、基线实际结果、候选实际结果。任何一侧未跑都写“未运行”，不能用 expected 替换 actual。展示实际命令、退出码、输出与隔离范围；没有声明测试写“没有运行测试”。
4. **应用区**：验证状态、已授权目标目录、是否存在漂移、应用动作。应用后显示目标目录、新分析引用/结果和撤销入口；失败保留提案与诊断。无 HTTP 写能力时明确如何启用对应已有能力，不渲染一个点了才说不支持的主要按钮。

单条验证先做成列表与源码对照；关系 diff 投影可复用调用图的 display model。布局应对齐未变对象，新增/删除用形状和文字区分，不整张图跳动。正在验证按 proposal/job ID 查询，切换函数不把结果挂到另一提案。

原型的报告展示“未运行”和目标状态样例，不声称已执行测试或应用。正式状态由后端控制，不能由点按钮直接变成功。

## 6. 3D/2.5D 结构定位

原型补了可选择的玻璃柱版面草图，验证它在同一工作空间里与源码/2D 共享对象。它不是最终 WebGL 渲染，也没有模拟执行。T1 可先保留现有 3D 页面；正式替换按 T3 接续，不让材质细节阻塞运行闭环。

正式渲染组成：目录分区地块 → 文件玻璃外壳 → 函数可选择层 → 带真实端点的调用管道。保持已有层级/尺度函数作为起点；聚合、大小压缩和省略始终可解释。一个巨型文件不能把其余文件压到不可见。

默认正交或弱透视 2.5D，稳定方向便于定位；允许转动但不强制用户绕柱找标签。外壳透明度只服务可读性，深度排序导致内部函数不可见时改用剖面/展开，不把透明渲染本身当交付目标。HTML/文本层保持标签清晰，密集区域折叠并提供列表。按目标层放置连接端口，跨目录路径通过边界端口，遮挡路径可选中单独突出。

同一分析的 2D/3D 共用 selection；各自保留相机/缩放/折叠。搜索对象可 reveal 到函数层，聚合对象先展开或显示成员，不能假称它就是某个文件。选择改源码使用真实实体，选择某次运行保留实例身份。未来有实际运行采样后，沿观察到的路径加独立 overlay，不改变静态几何/关系。

## 7. 前端状态与恢复

建议直接从现有 state 拆成小模块，无需先换框架：

```text
SelectionKey = analysisId + entityId
Workspace = project + analysisId + selected + task + lens + history
Resource = key + generation + status + data + error
Draft[SelectionKey] = args + this/globals + via + inputEditorMode + patchDraft
RunCache[SelectionKey] = latestRecordId + records + pendingRequest
ViewState = 2dViewport + 3dCamera + folds + sourceAnchor + panelWidths
```

- 搜索、节点、源码、关系、flow、profile、annotations、patches 全部按版本/实体缓存。请求完成先核对 key/generation，过期结果只写其缓存或丢弃，不改当前面板。
- 返回恢复对象、任务、镜头与源码位置；切换任务保留参数/补丁草稿和本次记录。切换分析版本时不静默把旧草稿应用到新对象。
- 请求错误读取服务端 JSON body，保留 error/detail/proposal；失败不是空列表。每个面板能独立重试。
- 首片会话内保存状态即可；后续保存工作区导航/相机，不把令牌、敏感输入和源码默认持久化到公开 URL。分享链接只含可用句柄与视图状态，材料披露沿现有边界。

## 8. 执行切片与完成标准

具体接口缺口、字段和代码入口见 [API 接线表](FRONTEND_API_CONTRACT.md)。执行者无需再选一个产品方向，按以下顺序接线：

| 切片 | 交付结果 | 核心核对 |
|---|---|---|
| F1 工作空间与真实选择 | 替换旧首屏组织；导航、关系、源码联动；各资源局部加载/错误 | 搜索非首屏函数；快速 A→B 切换；A 的迟到提案/源码不出现在 B |
| F2 值与未知依据 | 来源摘要和未知清单真正定位对应源码区间 | 长函数后部、UTF-8、无锚点、截断与重试 |
| F3 运行闭环 | 按参数编辑、画像条件、真实预检和结果，保留草稿 | 无效输入、返回 false、异常、拒绝、超时；取消只在真实接口支持后显示 |
| F4 审阅闭环 | 页面启动验证，展示静态差异和测试报告，再应用/撤销 | 未跑测试、失败/漂移、选区切换、已授权写入目录与撤销 |
| F5 连续工作与结构定位 | 恢复与 2D/3D 往返，不丢用户当前任务 | 同一选区、各自镜头、聚合 reveal、旧分析重定位/拒绝 |

F1–F3 对应 T1，F4 对应 T2，F5 对应 T3。每片先修其真实阻塞，复用已工作的部分，不把表格再扩展成大量规划子任务。截图、浏览器操作和数据一致性共同判断；无需逐像素复刻，但不能把主要能力重新塞回折叠框或只有 CLI 能完成的流程。

设计原型验证范围见 [设计检查记录](../evidence/design/2026-09-13-workbench/REPORT.md)。产品是否可用仍须接线后验证，原型检查不提升产品资格。
