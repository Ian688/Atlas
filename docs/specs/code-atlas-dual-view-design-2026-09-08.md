# Code Atlas 双视图设计：3D 结构空间与 2D 关系工作台

版本：1.1 · 2026-09-08。配套：主设计 2.0、算法规格 1.5、成熟能力规格 1.3、独立集成规格 1.3、长期任务书 1.7。本文为待实现的交互、投影算法和验收合同；未修改或验证当前产品的 2D 实现。

## 1. 产品决定与职责

2D 关系视图升级为正式工作视图，支持独立进入、完整 Review、局部 / 场景测试、标注与 AI Coding。原主设计中“小图参考 / WebGL 降级”的定位不足以涵盖此功能，按本合同扩展。3D / 2.5D 结构空间保持既定目录框、文件柱、函数层和管道语言。

3D 帮助理解对象归属、结构规模、局部在全局的位置；2D 根据当前问题重新组织依赖、调用、数据、分支和运行因果。用户可按任务切换，也可长期使用任一视图。2D 同样能浏览全项目的分层摘要，3D 同样能局部深入；不强制“先看 3D 才能用 2D”。

两者共用本地事实 / 分析引擎、运行库、选区、标注、设计意图和变更验证。2D 布局不调用 LLM，也不重新构造另一份代码真相图；LLM 按需解释、规划和 Coding，沿用本地上下文编译与披露合同。

“思维导图”描述阅读与交互感受，不要求把代码关系变成单根树。包含关系可用树；实际调用、共享依赖、递归、并发与多入口必须允许有向图、循环和多个父来源。几何上将 3D 的高度设为零不能完成这种语义重组。

## 2. 导航、进入与视图联动

工作台主切换提供“结构 3D / 关系 2D / 对照”，最后使用的模式按工作区记忆。关系视图内提供少量问题入口：结构、调用、数据、运行、变更；实现上对应不同 ProjectionSpec，用户不需要选择算法名称。

从任意实体 / 管道提供“在关系图中展开”，从 2D 节点提供“在结构中定位”。默认携带目标、当前事实快照、查询范围、图层、运行与回放游标；不同镜头可用不同布局 / 聚合，但未明确更改范围时不能悄悄扩大或缩小查询范围。返回原视图恢复其相机、缩放、折叠和固定布局。

对照模式默认共享选择、快照、运行与时间游标，分别保存布局、缩放和局部折叠。双向联动带 source_view_id 与 action_id，避免互相触发无限刷新；一次用户操作不重复启动测试或模型请求。低空间屏幕采用切换；宽屏允许主视图 + 可收起的概览定位区，不强迫长期等宽双屏。

用户锁定某视图时，Agent 的定位请求显示为可应用的建议，或按用户已经选择的自动跟随方式处理。跨版本对照必须显式显示左右快照，选择通过有证据的身份映射联动，歧义可见；不能伪装两侧仍是同一当前版本。

## 3. 五种问题视图

| 视图 | 回答的问题 | 本地关系与默认布局 |
|---|---|---|
| 结构 | 项目有哪些部分、某函数属于哪里 | contains / import / 配置依赖；可折叠层级框和文件卡，按需打开横向关系 |
| 调用 | 谁触发这里、这里又调用谁 | 目标居中，上游 / 下游分层；调用点、返回、递归与动态候选分开 |
| 数据 | 这个值从哪来、在哪里检查 / 改写、最后去哪 | 源到汇 / 控制切片、字段 / 端口 / 转换节点；只显示实际支持的分析与探针精度 |
| 运行 | 本次场景实际走过什么、何处失败或等待 | invocation / actor / task / message 的因果视图；顺序横向，跨 actor / 服务用泳道，重复实例可折叠 |
| 变更 | 新旧版本改变了哪些联系和行为 | 源码 / 契约 / 关系 diff；新旧布局锚点对齐，受影响测试与运行可跳转 |

目录与文件归属始终可从路径徽标 / 面包屑恢复，不必在每种图都展开全层文件框。业务分组是带来源的视图组，不能改写函数真实所属文件。自然语言业务名无可靠来源时显示原始符号名；用户 / LLM 命名作为注释或拟议映射，保留来源。

普通函数节点展示名称、文件路径、输入 / 输出摘要和状态；细节展开到源码 / 分支 / 端口，不把 50 行代码永久塞进每张卡片。CFG 分支和异常节点必须有源码 / IR 锚点，不能由可视化器凭函数名猜测。

## 4. 语义投影与简化规则

复用 AL-12 生成有界关系投影，AL-09 处理精确声明范围内的数据 / 控制切片，AL-13 提供运行实例和因果。查询可选整个项目的层级摘要或目标附近的详细子图；既保留导航到未显示对象的方法，也明确当前覆盖范围。

允许折叠同目录 / 同文件成员、递归簇和不改变当前解释焦点的中间链。每次折叠返回成员 / 路径引用、关系种类、方向、证据类别、计数与完整性；不存在精确计数时返回已知量和未知状态。不得显示无依据的全局总数。

关键分支、异常 / 权限 / 事务 / 外部 IO 边界、断言、未知段与用户固定对象默认保留或显式显示折叠标记。例如 A 经三个中间函数到 B 的摘要边注明“经 3 个函数”，点击展开；不得画成项目原有的 A 直接调用 B。可达性摘要、may-flow 与已观测路径分别标识，不把“图上可达”升级为“一定存在可执行路径”。

调用图的静态聚合按 symbol / callsite；运行镜头按 invocation 或带成员清单的调用实例组。函数在两条场景分支中重复出现时可画多个 display instance，但它们指向同一 canonical entity，且保留各自调用上下文。选择“改函数”去重到真实实体；选择“查这次调用的值”保留实例，不能混用两种语义。

边交叉只表示几何交叉，真正连接必须落到端口。多条边重合时保留方向、类型与成员选择，不靠颜色相近推断同一数据或因果。

## 5. 投影身份与协议扩展

ProjectionSpec 固定 owner / project、snapshot_id、analysis_revision、graph_layer、focus_refs、lens、关系与方向过滤、上下文深度、边界策略、预算，可选 run_id / replay_cursor 或基线 / 候选版本对。view_mode 只改变表现，lens / filters 改变查询语义；二者分别记录。选择一个新镜头可以启动局部分析，单纯切换维度不重新全仓解析。

以下是拟议参数示例，实际 schema 需补齐引用类型与错误合同；预算只是待测初始值，达到上限返回 partial / frontier：

```json
{
  "schema": "atlas.projection-spec.v1",
  "project_id": "delivery_demo",
  "snapshot_id": "snap_18",
  "analysis_revision": 4,
  "view_mode": "2d",
  "graph_layer": "code",
  "lens": "call",
  "focus_refs": ["symbol:redeemCoupon"],
  "direction": "both",
  "max_depth": 2,
  "budget": {"max_nodes": 80, "max_edges": 160},
  "preserve_boundaries": true
}
```

ViewProjection 返回 projection_id / revision、源 manifest、display_instance_id、canonical_refs、context_refs、聚合成员、summary_path_refs、可见 / 折叠 / 过滤 / 未知原因、分页与 frontier。完整运行中折叠重复实例时，成员次数必须按当前游标计算，不能提前显示未来执行次数。

SelectionEnvelope / InteractionRequest 继续保存 canonical 引用和快照，并增加可选 projection_ref / display_instance_ref / selection_semantics；聚合节点被选中时需冻结实际集合或明确查询范围。即使 2D 布局、3D 相机变化，标注的代码对象也不漂移。IntentGraph 与真实 CodeGraph 的身份空间仍分开。

WorkbenchState 增加各 pane 的 mode / lens / projection_ref、共享 selection / run / cursor、联动与固定状态。view_command 支持协商后的 set_mode / set_lens / reveal / focus / fit / seek；graph_query 等既有操作接收投影参数。MCP、WebMCP 与 Modus 适配共用这些操作，Agent 不需要识别坐标，也不能通过改图层制造事实。

## 6. 本地算法流水线与稳定性

1. 校验版本、实体、图层、范围和预算，固定不可变输入。按索引有界查询，数据切片采用 AL-09 的语义规则，不用普通 BFS 冒充可行数据路径。
2. 基于目标和问题镜头做层级聚合 / 摘要，保留真实成员、关键边界和未知前沿。显示简化不撤回 FactStore 中的事实。
3. 对当前已物化静态调用子图做 SCC 分解；递归簇收缩后分层，簇内提供返回边或展开。布局算法内部为排版反转边时，恢复真实箭头方向；不能改变业务关系。
4. 分层排序、节点放置与端口走线在本地 layout worker 执行。目标节点及用户固定节点作为锚点；新数据只对受影响区域重排。循环重试和并行分支保留关系，不强行拉直成成功路径。
5. 运行镜头使用已采集的 happens-before / span / message 关联安排泳道；时间戳只作时间信息，不能据此给并行事件虚构全局因果。
6. 生成本地文字、命中区、线型、颜色和无障碍语义列表；renderer 接收的是有界显示图，不是整仓事实库。

有界邻域 / SCC 的图遍历成本与已访问节点、边有关；路径语义求解和布局优化另计，不能统称全流程线性。布局使用有界迭代、deadline、取消和稳定种子；缓存键包含快照 / 分析 / 查询 / 折叠 / 节点尺寸 / 固定锚点 / 布局版本。trace 播放只更新样式与游标，不逐帧重排。

布局任务标记 generation，迟到结果不得覆盖新选区。超时返回稳定的简单分层 / 列表和显式简化状态，不阻断源码与报告访问。大项目总体资源沿用主设计预算；双屏不能各自按完整上限加载全量图，也不能各起一份索引和测试作业。

## 7. 连线特效与运行留痕

| 状态 | 2D 呈现 |
|---|---|
| 静态结构 / 当前选择 | 清晰箭头、关系标签、选择描边；悬停高亮局部，不播放伪造数据 |
| 显式计划预演 | 独立“计划”标识与线型，可逐步聚焦；不生成真实调用次数或通过结果 |
| 实际运行 / 回放 | 采集事件对应的线段发光，数据标记沿方向移动；节点显示此次输入 / 判断 / 输出 |
| 完成 / 失败 / 取消 / 等待 | 已经过的路线保留，其他未经过区域灰色静默；终止点和缺口可见 |
| 暂停 / 减少动效 | 保留色迹、箭头、时间 / 次数与值摘要，停止连续粒子，不丢掉运行含义 |

与 3D 使用同一数据类型色表和独立的告警符号。流水动效是事件的可视化表示，动画速度与密度不自动代表实际延迟、带宽或对象数量；需要表达指标时用已测数值和标尺。色彩变化只能对应有来源的数据转换；trace gap 两侧不能用连续粒子补成已观察传输。

单次运行共用 ReplayCursor、ActiveSet、VisitedSet、TrailSnapshot。切换 2D / 3D、打开源码、改选区、标注、关闭一个 pane 不清空留痕；回退游标不显示未来经过路线。高频路径可汇总次数和范围，用户进入具体调用时再看细节。

## 8. Review、测试与 AI Coding 的完整交互

在 2D 节点、边、端口或多选集合上提供查看源码、上下游、追值、设置输入、构造测试、标注约束、解释与修改。可测试性仍由 AL-16 决定；图上相连不代表可以任意复制函数体独立执行。依赖包络与用户选区、观测 / 写范围仍分开。

例如选择“红包核销”，展开两个订单 actor 的调用实例，输入“同一张券最多被一笔订单核销”。本地准备场景与断言，真实运行后定位竞争写入；LLM 读取版本化上下文与证据提出修改。相关对象在 3D 中可同时定位，运行回放留痕一致。

2D 拖动节点、整理连线、收起对象只改变视图；不能直接改代码。用户在两节点间画新线时形成显式 DesignIntent（如拟新增调用 / 数据映射），由现有 Coding 流程生成候选源码、解析、接入和验证。对已有连线的删除请求先区分隐藏关系与修改实现。2D / 3D 的 IntentGraph、ProposalBinding 和验证结果共用。

模型按需附加的功能解释绑定 snapshot / entity / invocation，显示来源与过期状态。自然语言复杂解释需要 token；布局、关系抽取、基本类型 / 输入输出显示、已有场景运行、选区同步不需要 token。用户标注提交仍使用冻结请求邮箱，不因切换 2D 另造聊天注入机制。

## 9. 可阅读性、导出与技术选型

视觉采用浅层卡片、细分组框、留白、稳定箭头与少量激活色。长函数名 / 路径可展开，标签碰撞时分级显示并可搜索；过密区域提供关系表 / 矩阵。全图常驻动画与持续力导向漂移不作为默认阅读方式。键盘、语义列表、高对比和减少动效为正式入口。

允许保存视图书签和按顺序组织讲解：保存查询、版本、选区、折叠、运行游标和注释，方便复现某个问题。SVG / 图片用于阅读，机器可读快照 / 查询 / 来源清单用于复验；导出均携带范围、版本、图层和省略说明。Mermaid 可作为有限子图的文档导出，但不能替代交互工作台和证据包。

技术候选不是已安装清单：优先沿用 ELK / elkjs 的本地布局方向，评估 Cytoscape.js 或独立 TypeScript renderer 作为关系图组件；如果宿主明确采用 React，再比较 React Flow 的节点 / 端口编辑成本。不为选一个图组件强制重写整个 Modus 前端，也不同时维护多个生产真相图。

- [ELK Layered](https://eclipse.dev/elk/reference/algorithms/org-eclipse-elk-layered.html)支持分层、端口、循环及跨层级关系，适合评估本场景；它提供布局而非代码语义。
- [Cytoscape.js](https://js.cytoscape.org/#notation/compound-nodes)提供复合节点和图交互；其普通图遍历不会自动将父组解释为所有子节点关系，Atlas 必须明确成员查询语义，嵌套渲染成本也需实测。
- [React Flow 布局文档](https://reactflow.dev/learn/layouting/layouting)列出布局库和子图限制；交互组件、布局算法与代码分析是分别承担的工作。
- [An Overview + Detail Layout for Visualizing Compound Graphs](https://arxiv.org/abs/2408.04045)讨论展开细节时保留高层结构的布局，可借鉴其概览 / 细节组织。论文不证明 Atlas 的 2D / 3D 组合已经更高效。

正式选型用同一有界 fixture 比较标签可读性、选取误差、稳定性、布局 / 帧时间、资源与可访问性。先评估实现成本和实际任务表现，再固定版本与许可；不按 demo 好评或节点数宣传直接决定。

DV 是这些包及原 A / C / T / MT / HI 的细化，原 33 个工作包、17 项 AL / 52 个 ET 仍有效。文档结构检查不代表这些用例已经执行；发布的双视图能力须有实际 fixture、UI、运行回执和用户任务证据。

## 11. 首轮实现后的完整度与投影约束

1.1 补强 [实际审查](code-atlas-implementation-review-2026-09-08.md) 发现的分页/统计/边界缺口。当前 preview adapter 是真实数据入口，但不等于本规格的正式双视图已完成。

信息完整度与绘制数量独立：所有清点目录、文件、链接、未采集/未支持材料和明确排除边界可定位；视口可以只绘制聚合或一页。不得因不存在 content blob 就让实体从树中消失，不得把 limit=200/100 的首屏当作全项目/全文件。

ProjectionResponse 带版本、查询范围、total/loaded/unknown 计数、truncation reasons、continuation 和边界端口。exact count、估计值和未知三态区分；文件柱高来自对应统计范围，不随已加载页面数悄悄改变语义。目录框提供聚合、钻取、搜索直达；函数层通过虚拟化/抽屉细节承载 10/50/数百函数，不强迫全部名字重叠显示。

2D/3D 共用 selection、snapshot、run 和 replay cursor；布局、相机和折叠可以独立。图的端点被预算省略时，画 boundary port/stub 和继续展开入口；不能画一条似乎完整的线路却没有去处。投影过程不调用模型，不从源码重新推导第二套关系。

颜色和留痕消费证据层：静态 may-path、计划、真实 observed、failed、unobserved 明确区分。trace complete 只在规定采集范围内解释，零事件/缺目标不能让全图成为“确认未执行”。运行/失败/取消后保留已观察路线，其他未经过区域灰色；未观测区域额外保留覆盖标记。数据粒子的动画速度可缩放，但不能更改事件因果顺序；并发跨线程用偏序/并行关系，不制造全局顺序事实。

新增 DV 反例归入原用例：目录超过 200 项、文件超过 100 函数、symlink 无 blob、预算裁掉端点、跨版本迟到响应、双视图联动循环、重复 run、无 trace 覆盖、失败/取消后轨迹留存。先用真实服务和浏览器验证信息可达/身份一致，再评估玻璃材质、布局稳定与任务可读性。
