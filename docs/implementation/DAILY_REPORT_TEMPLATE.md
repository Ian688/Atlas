# Atlas 阶段开发交付模板

此文件是模板，不是一次已完成交付。复制到窗口 `final/daily-report.md` 后填入事实；占位符不能作为证据。

## 窗口与代码身份

| 字段 | 实际值 |
|---|---|
| window_id / status | 待填写 |
| 开始、结束、时区、UTC | 待填写 |
| 中断及恢复 | 待填写；关联实际断点 |
| cwd / branch / HEAD（若存在） | 待填写 |
| 起始与最终源码清单/指纹 | 待填写 |
| 完整 changes.patch / changes.json | 待填写；含原 untracked 文件 |
| 前一窗口与复审结论 | 首次执行填 NONE |

## 本次实现及可运行结果

逐项说明用户现在能做什么、触发路径、改了什么及其原因；不要只列新文件和代码行数。

| W / feature / profile | implementation | automated_checks | qualification | review_status | 代码/命令/证据 |
|---|---|---|---|---|---|
| 待填写 | NOT_IMPLEMENTED / PARTIAL / IMPLEMENTED | NOT_RUN / PASS / FAIL / BLOCKED | NOT_QUALIFIED / QUALIFIED_WITHIN_PROFILE | NEEDS_INDEPENDENT_REVIEW 等 | 待填写 |

分开列出新增能力、修复、部分能力和未开始工作。使用 mock/replay 的项目写明来源；没有真实 provider、浏览器、环境或规模资格的，不借基础 PASS 泛化。

|---|---|---|---|---|---|
| 待填写 | 待填写 | 待填写 | 未运行不得填 0 | 待填写 | 待填写 |

提供一个能由复审者从当前源码重新索引、查询、定位结果的完整小样本。列出真值/来源/候选集合/unknown/truncation 的预期，不能只说“程序没有报错”。如修改 UI，说明实际点击、API 结果、当前分析版本及图中成员；截图不是数据流正确性的唯一证据。

## 资源、生命周期与兼容

记录受影响操作的耗时、访问量/预算、可得的内存数据及测量方法，不能从输出条数反推内部工作量。列出取消/期限/worker 故障/输出超限/旧版本与游标隔离的适用检查。协议、schema、数据库迁移、CLI 参数和旧查询兼容如有变化单独说明。

## 未解决项与真实失败

每项写复现步骤、最小输入、期望/实际、影响面、当前配置是否启用、临时处理及下一步。超时/中断/阻塞要有实际工具结果；不通过删测试、放宽断言、重写 golden 或把支持项全部标 unknown 清零。

## 请求独立审查

列出你最希望复审者检查的 3–5 个合同/算法结论，给出精确文件/符号、最小反例和可复现命令。请明确哪些结论只是实现者自测，不能写成独立 ACCEPTED。

## 下一步

给出下一项 W、当前函数/文件、具体改动、应先重放的失败命令和通过条件；写清依赖，避免“继续完善算法”这类无法执行的概述。有实际阻塞时说明原因和可继续推进的其他工作。
