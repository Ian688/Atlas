## 1. 当前目标：交付首个完整可用的 Atlas 本地版本

用户决定先把产品做完并交付，再补细节。本轮交付一个可在已验证本机平台安装/解压启动、打开自己的 JS/TS 项目、理解并运行函数、验证和审阅修改、应用或撤销、关闭后继续工作的版本。完成线覆盖用户旅程；长期全规格仍保留，不要求本轮全部实现。

当前队列按下面顺序连续推进，完成一步直接进入下一步，已工作的部分复用：

| 顺序 | 用户结果 | 本轮完成线 |
|---|---|---|
| D0 修复已有阻断 | 已交付界面可靠可用 | 复验并修复前端独立报告 R1–R4：验证切换卡死、全局依赖漏报、验证身份、连线坐标；已修复则跳过 |
| D1 完成 T1 | 找到函数、看懂依据、实际运行 | 真实查找与关系/值/未知联动源码；参数和所缺条件可配置；结果归属正确、失败有下一步；至少能比较同一目标两次输入/结果 |
| D2 完成 T2 | 审阅并落实修改 | 多行源码增删、实际关系变化可定位；隔离验证和显式配置的测试有真实结果；授权临时项目应用/撤销经字节验证；支持的目标以相同输入对照修改前后运行结果，不支持则说明，不伪造 |
| D3 完成 T3 | 打开自己的项目并继续工作 | 可接受项目路径的稳定启动入口；分析状态、失败/重试、取消分析可达；重开恢复项目与有效选区/页签/草稿；2D/3D 往返定位同一对象，版本变化明确处理 |
| D4 本地交付 | 用户能按说明独立使用 | 构建可复现的本机分发目录/归档，包含必要 worker/静态资源、启动入口、依赖检查和简短使用说明；从仓库外启动并走通完整旅程；标明已验证平台和依赖 |

首版前端：2D 是主操作台，保留左侧查找/最近项目或对象、中央任务视图、侧边源码依据、显著主动作。按“理解、运行、审阅”组织信息；结果与下一步放前面，技术诊断可展开。3D 保留项目结构定位与 2D 联动。关系接线正确、diff 可读、操作反馈及时、长内容可滚动属于交付内容。材质、复杂动效、精细相机恢复可随后增强。

优先在 `examples/tour` 和不同结构的独立 JS/TS 小项目完成全程。保留明确动态语义边界；不因尚不支持任意函数而停下整个产品，也不把可支持的普通场景改成 unknown 来绕过错误。

本轮可后加：全语言、完整 Source/Scenario Trace、复杂上下文自动合成、LLM 自动编程闭环、大仓库正式资格、Modus 迁移、跨平台安装器/签名/自动更新。首版通过现有接口导出证据与接收补丁，不依赖模型。默认完成本机本地交付，不自动上传或公开发布。

## 2. 开工：少读、先跑、找到真实断点

```sh
git status --short
git rev-parse HEAD
```

读 [HANDOFF](HANDOFF.md) 与 [progress.json](implementation/progress.json) 的当前动作，核对相关源码；历史记录不必通读。先实际操作下列 T1 路径。已经能用的步骤直接复用，从第一个失败或缺失步骤开工，别重复建设。

必要时安装/构建；依赖已就绪不必重复安装：

```sh
npm ci --prefix workers/typescript --ignore-scripts --no-audit --no-fund
cargo build --workspace --locked
ATLAS_DEMO_STORE="$(mktemp -d /tmp/atlas-t1.XXXXXX)" bash scripts/demo.sh
```

demo 命令持续运行，打印本地地址；在另一终端/浏览器验证，结束后停止自己启动的服务。使用独立 store 避免与其他会话互扰。地址含会话令牌，只本地使用，交付日志和截图移除令牌。此启动方式是现有开发入口，不是最终安装体验。

开工更新只需说清：本次用户结果、当前断点、接下来修改的位置。无需先写新规划或建立新框架。

## 3. T1 逐步验收与默认实现路径

| 操作 | 应看见的结果 | 优先检查的现有入口 |
|---|---|---|
| 从页面查找一个函数，包括不在第一页的函数 | 名称和文件可区分；有明确空结果/加载失败；可选中 | `web/app.js`、`web/index.html`、`crates/atlas-engine/src/query.rs` |
| 选中并沿关系点击相邻函数 | 标题、源码、关系和输入面板指向同一对象；显示真实邻居，异步旧结果不覆盖新选区 | `web/app.js`、`web/layout.js`、`crates/atlas-app/src/server.rs` |
| 查看关键值来源与未知条目 | 结论易读；有来源则定位其源码区间，无事实则说清原因；已知部分仍可用 | `web/app.js`、`web/style.css`、`crates/atlas-engine/src/query.rs` |
| 打开运行入口并填写输入 | 所选目标明确，输入/所缺条件可编辑或有具体说明；不把内部字段原样堆给用户 | `web/app.js` 的 profile/exec 消费路径、`server.rs` |
| 执行可运行样本，再执行失败样本 | 真实返回或异常；拒绝/超时/取消与成功不同；可查看输入和对应源码 | `scripts/test_execution.py` 对应产品路径 |
| 切换函数或返回前一视图，再导出上下文 | 旧结果不冒充新对象，导出固定到所选版本与实体 | `web/app.js` 的 selection/context 路径 |

上述是验收目标，不声称这些步骤现在都可用。先读已有 handler 和请求，再改代码。默认复用现有选区、接口、运行及补丁链；确实不适用时可以替换并迁移调用者。不要新增一条与现有事实脱节的演示链。

底层精度缺口只在影响本任务判断时修复。对不支持的动态行为提供明确边界；对已承诺支持的普通语义修实现，不把它全改成 unknown 来通过测试。设计选择以能读懂、能完成操作为准，不以卡片数、玻璃效果或模块数抵扣用户任务。

T2 接续入口：`web/app.js` 的 `renderPatches` / `proposePatch` / `writePatch`，`server.rs` 与 `scripts/test_patch.py`。先核对已有 HTTP/CLI 能力，补齐页面到真实验证结果的缺口，再做前后对照。涉及写入继续使用既有授权边界。

T3 接续入口：`scripts/demo.py` / `scripts/demo.sh`、`web/app.js` / `web/city3d.js` 的选区和恢复路径、`web/hierarchy.js`。先复现“关闭再打开”和“2D/3D 往返”丢了什么状态，再补最小持久状态。

## 4. 快速执行规则

- 优先解决主路径上第一个阻塞。常规实现、重构、布局库、参数和辅助依赖自行决定；把选择和理由写一句即可。
- 每项底层工作关联到一条验收结果。非阻塞美化、通用框架、遥远规模优化写入待办后回主线，不顺手扩散。
- 同一失败连续两次尝试没有新证据：缩成最小复现，列出尚未排除的原因，用一次能区分原因的观察再决定修改。不要只重跑、加超时或继续猜。
- 方案过重时先找现有通路或成熟组件。无需为了保留旧实现承担不必要复杂度；也无需为简单页面改动重构整个引擎。
- 发现外部阻塞，记录失败和解锁条件，推进独立步骤。只有所有当前可推进工作都依赖外部条件时才结束并说明；缺少某个浏览器驱动不是“所有浏览器都不能点击”的证明。
- 每完成一个可用步骤简要报结果和下一个阻塞。报告、测试和整理服务于开发，不作为反复绕开的主任务。

## 5. 验证：迭代时小而准，交付时查完整路径

按改动选检查，不要求每次编辑跑全套，也不固定测试数量：

| 修改范围 | 快速检查入口 |
|---|---|
| 2D 页面交互 | `node web/tests/app.behavior.test.mjs` |
| 布局/层级/3D | `node scripts/bench_view_layout.mjs`、`node web/tests/city3d.behavior.test.mjs`；选受影响项 |
| worker 语义 | `npm test --prefix workers/typescript` 与对应语义反例 |
| Rust | `cargo test --workspace --locked <相关测试名>`；涉及新二进制先构建 |
| HTTP/完整查询 | `python3 scripts/test_integration.py` |
| 运行/补丁 | `python3 scripts/test_execution.py` / `python3 scripts/test_patch.py`；选受影响链路 |
| 文档 | 链接/命令/状态一致性、`git diff --check`；无需重跑产品测试 |

UI 交付实际启动页面并通过可用的浏览器自动化、CDP、Playwright 或人工完成操作；记录操作和结果，截图辅助判断布局。DOM 模拟、接口调用和深链接截图各有用途，不能代替实际点击路径。工具不可用时保留这一项未验证，继续可做的实现与检查。无需为采用某个驱动先开发通用测试平台。

产品阶段交付前运行现有综合检查（同一批未再改变的源码只跑一次；失败或后续修改才补相关复验）：

```sh
python3 scripts/verify.py --label <本次标签> --out evidence/development/<唯一目录> --keep-going
git diff --check
```

保留最终退出码、真实失败和检查范围。新功能新增能发现真实回归的关键检查，复用现有入口，不写只复述实现的测试。发布环境/规模资格按声明范围单独验证，不拿全规格门槛阻止 T1 开发，也不拿 T1 通过冒充完整产品合格。

## 6. 交付与接续：只维护一个断点

一份 [简短报告](implementation/DAILY_REPORT_TEMPLATE.md) 加 progress 当前动作即可：用户新增能力、改动、验证与退出码、剩余阻塞、下一步。源码身份引用实际 HEAD + diff/新增文件；不要另造重复台账。报告放新的证据目录，历史结果不覆盖。

自测通过标为 `NEEDS_INDEPENDENT_REVIEW`；复审结论由实际复审产生。未做部分写清，避免“整体完成”。复审等待不阻止独立的已授权后续任务。

Git 提交按当前授权执行，不强制每个小步骤提交，也不要求整个共享工作树干净。只处理自己负责的改动，不自动 push、发布或清理他人文件。

## 7. 只保留必要边界

本地解析不执行用户代码或调用模型；运行和写入按授权进行。本地数据不默认外传。源码版本/对象身份明确，发布事实不可暗改，未知与覆盖可见，工作有界可取消，静态/观测/意图区分。除这些产品边界和用户明确决定外，旧路径、阶段编号、数值默认值和工具经验均可调整。
