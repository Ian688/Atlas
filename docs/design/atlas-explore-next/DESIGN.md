# Atlas 探索代码：项目地图与多展示区

这是一份新的探索页设计，供用户看界面、试操作和决定下一轮实现。可点击原型见 `index.html`，不替换现有产品。沿用 Atlas 本地工作台、开发者与编程 Agent 共用代码依据的定位。

## 1. 页面要帮用户完成什么

打开一个项目，先知道它由什么组成；沿目录进入文件和函数，同时保留大图。遇到不理解的节点，查看不同来源的解释，记下自己的理解；遇到问题，围绕同一节点和 Agent 讨论、提出修改、运行测试、审阅结果。

**一个项目地图，可以同时打开多个分析区域；每个区域可以放多个节点标签。** “选中”“展开”“打开”各司其职，不因看一个函数而丢掉整个项目。

## 2. 页面布局

| 区域 | 页面位置 | 放什么 |
|---|---|---|
| A 项目与工作区 | 左侧窄栏 | 产品导航、展示区列表、关注节点；展示区多时从这里直接找回 |
| B 搜索与视图管理 | 顶部 | 全项目节点/路径/批注搜索、目录索引开关、详情开关、布局与保存工作区 |
| C 多展示区 | 页面主体 | 每个区域自己的标签条、路径、地图/内容/关系切换、缩放、展开、选区和滚动位置 |
| D 节点详情 | 右侧，可收起 | 当前区域选中节点的简介、解析记录、批注、按节点类型提供的操作 |

默认：一个项目地图展示区，根节点为当前项目名；目录索引默认收起，避免一开始有两份树抢空间。右侧先显示项目简介。初次打开项目时显示项目及首层成员；示例稿为了展示完整层级，预展开到 money.ts 的函数。

点击节点只更新选区与详情；点展开按钮只展开结构；双击/Enter 在当前区打开节点标签；`… → 在新展示区域打开此节点` 建立一个独立区域。详情是全局侧栏，跟随当前激活区；需要固定查看的内容应打开为区域标签。

## 3. 树如何展开

```text
项目
├─ 任意深度的文件夹
│  ├─ 子文件夹
│  │  └─ 代码文件
│  │     ├─ 顶层函数
│  │     ├─ 类 / 方法
│  │     └─ 可定位的常量、导出项
│  └─ 普通文件
│     ├─ Markdown 标题 / 章节
│     ├─ 配置键（有对应解析器时）
│     └─ 文件全文 / 内容片段
└─ 根目录文件
```

目录按真实路径递归，不能用“顶层目录”代替中间所有层。文件与目录可以出现在每一层。代码文件成员由当前语言分析能力提供，不能把未知内容猜成函数。未支持的语言仍有文件节点、文本预览、批注、交接入口；二进制文件显示类型/大小/可用预览，不伪造文本。

函数默认到函数节点；内部语句、分支、值来源在用户选择“深入函数”时按需展开。不会把整个项目的每行代码一次性生成节点。非代码文件默认全文，需要时再按章节或有意义的内容片段展开。

地图默认只画**包含关系**。点“关系”再查看调用/引用/依赖，不把代码目录树和调用图混在一起。关系视图仍可以打开目标、批注和读简介。

大项目处理：按父节点加载成员，单层支持分页；搜索在全项目索引中进行，命中可直接打开，不依赖画布当前加载的节点。超多同级节点先按目录/文件收拢，显示真实成员数和“继续加载”。缩小到概览时减少细节；默认分区不把文字缩成不可读的点，超出画布用平移、滚动或在新区聚焦子树。小地图、过滤和邻接关系上限可在实际大项目体验时再调。

## 4. 标签与展示区管理

| 用户动作 | 结果 |
|---|---|
| 单击节点 | 高亮节点，右侧展示该节点详情；不替换已打开的标签 |
| 双击节点 / Enter | 在当前区域新建节点标签；该区域已有相同节点/版本则激活 |
| 在新展示区域打开 | 新区域以该节点为根，可继续展开自己的树；原区域保持不动 |
| 地图 / 内容 / 关系 | 同一标签的三种视图，身份不变；内容视图可承载源码或普通文档 |
| 在项目中定位 | 返回项目根标签并展开祖先路径，保留原节点标签 |
| 左右 / 上下分区 | 改变呈现，保留每区的标签、选区和编辑草稿 |
| 最大化 | 暂时只看一个区域，其他区域保留；再次点击还原 |
| 关闭标签 / 区域 | 只关闭视图；已保存解析与批注仍属于节点，可再次打开 |
| 保存工作区 / 重开 | 按项目恢复区域、标签、激活项、展开、缩放、草稿和过滤 |
| 项目或代码版本改变 | 标签继续标明原版本；用户选择重定位到新版本，失效节点说明原因 |

建议桌面常用两区，四区用于短时比较；更多节点优先放标签。不要把“四区”做成产品硬上限，实际可以把超出可见范围的区域收进区域列表。正式实现支持拖动分隔线、标签重排/移动到别区、关闭其他标签与恢复刚关闭区域。窄屏一次展示一个主区，详情成为抽屉；不把所有内容挤成窄列。

同一节点可以在两个区域分别看源码和调用关系。区域之间默认独立；如提供“跟随区域 1 的选区”，必须有可见开关，关闭后恢复独立。不要让某一块重新加载清空其他块。

## 5. `i`：三种来源，加一份可编辑的解析记录

点击任何节点右上角 `i`，详情区有三张来源标签：

| 来源 | 显示内容 | 生成与编辑 |
|---|---|---|
| Atlas 摘要 | 项目/目录的成员和入口；文件导出与依赖；函数签名、读取/返回/调用候选、已知限制。按已有算法结果组织文字 | 不需要模型。引用原事实；用户可以引用到自己的解析中编辑 |
| 代码注释 | 源码直接关联注释、文档字符串；项目简介可引用 README/包描述，但明确来源 | 原文与文件位置可跳转。没有注释就说没有；编辑解析不改源码注释 |
| LLM 解释 | 用户请求后产生的职责说明、业务解释、边界疑问 | 点击“生成解释”→ 选择模型、查看节点及关联上下文范围 → 再次点击生成；结果先作为候选解释 |

下方始终有“Atlas 解析记录”编辑区。可以引用一种或多种来源，也可以直接写。保存后成为该节点的解析条目，显示作者、依据版本、来源和保存时间；原始算法事实、源码注释不被覆盖。重新生成 LLM 解释也不自动覆盖用户已保存内容。

解析可以有历史修订。代码更新后保留旧记录并标“待核对”，用户可并排看代码变更、更新解释，再保存新修订。最终的“Atlas 对这段代码的解析”是用户确认的知识记录，并不冒充算法已经证明的结论。

生成中、失败、取消、重试、未配置模型都要有可操作的状态。没有配置模型时保留“复制上下文到外部 Agent”的入口。模型请求仅在用户点击生成/发送后发出；生成过程中切换节点，结果仍回到发起节点和固定版本。

## 6. `…`：所有节点共有的动作

固定放最前面：**在新展示区域打开、在当前区新建标签、查看简介、批注、关注、复制路径/固定引用**。菜单后半段随节点类型变化，避免给目录显示“运行函数”之类无意义的操作。

| 节点类型 | 理解与导航 | 常用操作 / Review | AI Coding 任务 |
|---|---|---|---|
| 项目 | 入口、模块关系、目录地图、分析范围、README | 搜索全项目；查看本项目变更；重新分析；查看诊断 | 带新人理解项目、实现一项需求、定位问题涉及哪些模块 |
| 目录 | 子树、模块职责、跨目录依赖、文件列表 | 搜索此目录；按目录审阅；关注此模块 | 梳理模块边界、局部重构、补文档/测试 |
| 代码文件 | 源码、导出项、导入依赖、引用位置 | 多标签读源码；文件 diff；检查关联测试 | 文件级解释、重构、修复、补测试；重命名/移动先生成可审阅变更 |
| 函数/方法 | 签名、源码、调用方/被调用方、值来源、未知条件 | 准备输入并运行；历史；同输入对照；函数相关变更 | 解释分支、讨论边界、定位错误、生成用例、提出补丁 |
| 常量/类型等声明 | 定义、引用、所属文件 | 查看引用影响、审阅声明变化 | 调整声明、同步引用、补说明；不提供无意义的直接运行 |
| 普通文件/章节 | 全文、章节、关联引用、元数据 | 搜索内容；文件 diff；批注内容片段 | 解释配置、完善文档、检查描述与源码是否一致 |

AI Coding 菜单先展开为具体意图：**解释、找问题、补测试、修改、重构、补文档**。选择后生成可编辑的任务草稿，包含当前节点、范围、用户目标、引用的批注和解析、预期验证方式。无需每次让用户从零写提示词。

Review 统一落到已有提案系统：当前节点相关提案列表 → diff → 测试与前后对照 → 确认应用/撤销。树上可以显示“有提案/已改动”的标记，点击定位具体提案。不能把模型口头建议显示成已经修改或验证成功。

## 7. 批注 → 对话 → 修改

1. 用户在节点上写批注；默认绑定本节点和固定版本，可选择进一步锚定代码片段。
2. 点击“带批注发给 Agent”，先看到要交接的范围、已有记录和具体问题，可以增删关联节点。
3. 有连接时选择 Agent 会话并明确发送；无连接时复制/导出交接包，也可先保存本地草稿。两种方式都可用。
4. 用户可以在这个节点的讨论里追加意见；新的讨论消息不自动改变已有解析记录。
5. Agent 返回说明、问题或补丁。说明可引用进解析；补丁进入同节点的 Review。收到、排队、执行中等状态必须来自实际连接，不能由 UI 自己猜。
6. 应用后创建新分析，地图定位到新代码；旧讨论、旧解释和旧测试仍保留其原版本。

每条交接应有自己的身份，用于关联节点、批注、任务与提案。现有外部 Agent 桥接接口不等于已具备模型生成或聊天连接，正式接入时核对能力；首版可先完整支持复制交接与提案导入。

## 8. 技术栈与实现落点

保留当前 Rust 服务、语言 worker、原生 JS/CSS、SVG 和现有布局引擎，按需要拆分组件即可；不把设计稿里的自写小树布局用于大项目生产。

| 设计组件 | 复用能力 | 需要补齐 |
|---|---|---|
| ProjectMap / NodeCard | 当前节点/源码/搜索、hierarchy.js、layout.js | 递归路径结构与按父节点分页的成员查询；包含树独立于调用图；DOM 节点按钮 + SVG 连线 |
| Workspace / ViewGroup / NodeTab | 当前 ui-state 持久化、选区与 relocate | 独立区域状态、每标签异步请求代次；拖动布局、标签管理、版本失效提示 |
| NodeInspector | source / profile / flow / reach 等已有查询 | 按节点类型聚合摘要、源码注释提取与引用锚点 |
| Interpretation / Comment | 当前 annotation 能力可复用一部分 | 可编辑解析及历史、引用来源、片段锚点、草稿、待核对标记；不要假定现有 annotation schema 已全部支持 |
| LLM Explanation | 可导出的固定上下文 | 模型连接、范围预览、生成/取消/失败状态；这一能力目前不能靠前端按钮假装完成 |
| Agent Handoff / Discussion | 当前上下文导出、Agent/提案接口 | 交接与提案的持久关联、会话适配、讨论记录；未连接时真实显示复制/导出路径 |
| Node Actions | 当前运行、历史、patch 验证/对照/应用/撤销、3D 定位 | 按类型与实际能力决定动作，统一传递项目/版本/对象/提案身份 |

状态至少包括 `projectKey + analysisId + entityId/文档锚点`。项目切换时整组恢复，不复用另一个项目的同名节点草稿；历史运行按记录本身标版本。写入与重索引复用刚验收通过的当前项目授权机制。保存布局的精确字段由实现者决定，不另建并行规则系统。

大项目请求返回“成员总数、已加载量、下一页、未解析/未支持”等实际信息。具体 API 可以扩展现有接口或新增成员查询，本稿不声称新的端点已经存在。

## 9. 实现顺序与完成线

1. **项目地图 + 节点动作**：打开真实项目自动到根地图；递归展开文件夹/文件/成员，搜索并定位未加载节点；节点 i/… 正常工作。
2. **多标签 + 多区域**：一个区域继续看项目树，另一个读具体函数；关闭、恢复、最大化、布局改变均不串状态。
3. **摘要、注释、解析与批注**：显示真实来源；编辑保存并重开可恢复；代码变化时旧记录可识别。
4. **节点任务闭环**：批注 → 可复制或真正发送的交接 → 实际提案 → Review → 运行/对照 → 应用/撤销后回到地图同节点。
5. **按需模型解释**：明确配置与发送范围，生成结果与用户解析分开。若模型尚未连接，保持可用的外部 Agent 工作路径。

验收用一个包含多层目录、代码、文档和同名函数的真实项目；再用第二个项目核对工作区和记录隔离。先交一个可完成的页面任务，不先建设通用知识库或任意插件平台。

## 10. 原型已经做了什么

可实际点击：树展开/折叠、节点选择、i/类型菜单、搜索、节点标签、多个区域、左右/上下布局、最大化、源码与示例调用关系、三来源切换、显式 LLM 生成演示、引用/编辑/保存/历史、批注、交接草稿与示例对话、关注、刷新恢复、版本变更提示、区域标注。

仍为设计说明而非原型完整实现：可拖动分隔线/标签、真正的大项目分页与性能、多语言成员解析、真实模型与聊天连接、实际执行/写入、多个真实项目的切换、自动重定位、完整键盘树导航。本稿所有数据是示例，不能作为生产能力验收。

原型笔记仅保存在当前浏览器 origin 的 localStorage；可以“重置演示”清空。每次点击演示生成都清楚标识，无外部模型请求。


## 阶段与目标架构

实现同时遵循 [统一设计第 0 节](../../PRODUCT_DESIGN.md) 的架构责任。原型样本与阶段范围不定义仓库大小、语法深度、语言或关系种类的上限。当前路径上的深层解析和索引缺陷纳入修复；新增能力通过相同版本身份、适配器与按需查询接入。
