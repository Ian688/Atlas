## 照着交付的界面

### A. 页面结构

- 左侧：已有产品导航、打开的展示区列表、关注节点。
- 顶部：全项目搜索、目录索引开关、节点详情开关、布局切换、新建展示区、保存工作区。
- 中央：一个或多个展示区。每区有独立标签条、路径、地图/内容/关系切换、缩放/适应画布、返回项目定位、最大化与关闭。
- 右侧：当前激活区域选中节点的简介、批注、操作。可收起，窄屏用抽屉。

保留设计的浅色、低干扰背景、清楚的节点卡片与层级连线。尺寸、组件拆分和库选择可调整，以真实代码长度和可读性为准。不能把信息重新堆回旧的大段调试文字。

打开真实项目后，根节点必须是该项目名，不能保留 Papertrail、charge、固定 v18 或示例计数。原型顶部的“交互设计稿”、演示生成/执行按钮、模拟更新开关均不进入正式产品。

### B. 项目树的内容

- 按真实路径递归：项目 → 目录/文件 → 更深目录/文件 → 代码声明或文件内容，不丢中间目录。
- 代码成员来自实际分析；函数、方法、类、常量等按当前能力呈现。类型支持由语言能力声明决定；缺失类型给出真实状态。核心成员身份与查询保持语言无关，通过语言适配器扩展；阻塞当前目标项目的解析缺陷贯通修复。
- 普通文本可全文阅读；Markdown 至少支持按标题进入章节。配置文件当前提供原文阅读，结构化成员通过同一带版本的成员查询接入格式适配器。二进制显示元信息和可用预览。
- 默认展开项目和首层成员，继续展开才取成员。初始选中项目，右侧展示其实际摘要。
- 包含树与调用/引用关系分开；关系视图通过显式切换进入，连线含义与未知边界可见。
- 全项目搜索能找到未展开、未加载到画布的节点；结果保留路径，打开后可定位祖先链。
- 成员分页、总数、未加载、解析失败和不支持分别显示。不要通过一次读取全项目所有源码再前端过滤来假装按需加载。

### C. 节点点击契约

| 控件/动作 | 必须出现的结果 |
|---|---|
| 单击节点 | 更新该区域选区与右侧详情；已有标签和其他区域内容不被替换 |
| 展开/折叠按钮 | 只改变这棵树的结构展开状态；不意外打开标签或触发源码操作 |
| 双击 / Enter | 当前区域新建节点标签；本区域已有相同节点/版本时激活它 |
| 右上角 i | 打开该节点三来源简介，节点和版本清楚可见 |
| 右上角 … | 显示按节点类型变化的菜单；支持键盘与触摸，不能仅 hover 可见 |
| 在新展示区域打开 | 新增独立区域，以该节点为根；原地图保留；新区域可继续展开自己的树 |
| 在项目中定位 | 打开根地图、展开祖先路径并定位；保留原标签 |
| 地图 / 内容 / 关系 | 同一节点与固定版本的视图切换，不偷偷换对象 |

### D. 标签和展示区管理

每个区域独立保存根节点、标签、选区、展开、滚动和缩放。共享的右侧详情跟随激活区，不能让一个全局 selected 变量驱动所有区域重绘成同一个函数。

必须实现：多标签、关闭、关闭其他标签、恢复刚关闭标签/区域、标签重排与移到其他区域、左右/上下布局、拖动分隔线、最大化/还原、保存/重开工作区。移动标签可提供菜单方式作为拖动的无障碍替代。

常用两区，区域太多时通过区域列表切换或收纳，避免压成无法操作的窄条。不要把原型显示几区当作产品硬限制。空区告诉用户如何打开节点；关闭视图不删除解析和批注；未保存草稿要保留或在离开前明确处理。

切项目后恢复该项目自己的工作区。重新分析后旧标签保持原版本身份，用户可重定位到新版本；无法访问的旧节点显示版本失效和恢复入口，不能拿当前源码冒充旧源码。多个区域的请求与迟到响应互不覆盖。

### E. 简介与解析记录

1. **Atlas 摘要**：从真实结构和静态事实组织可读简介。项目/目录描述成员与入口，文件描述导入/导出，函数描述签名、读取/返回/调用及未知。没有模型也能使用。不要把 CFG/调试 JSON 当默认简介。
2. **代码注释**：原文引用，带来源文件和定位。项目简介引用 README 或包描述时明确来源。没有注释显示空态；编辑解析不直接修改源码注释。
3. **LLM 解释**：默认未生成。选择模型/连接与上下文范围后，用户再次点击生成才请求；显示生成、取消、失败重试。结果标明模型来源与对应节点/版本。
4. **Atlas 解析记录**：用户可引用一项或多项来源、自己编辑并保存。保存作者、时间、依据版本、来源引用和修订历史。刷新、重启服务后能读回；不能只依赖当前浏览器 localStorage 保存正式记录。
5. 新模型解释不覆盖用户已保存文字；代码更新后旧记录标记待核对，用户更新后保存新修订。

“LLM 没有接好”不能阻止算法摘要、注释、手动解析和批注先交付。也不能用 setTimeout 和固定回答把 LLM 项标成完成。模型接入见 M5 的具体处理。

### F. 节点操作菜单

所有节点共有：新展示区打开、当前区新标签、简介、批注、关注、复制路径/固定引用。之后提供适用动作：

| 类型 | 必须接通的常用动作 |
|---|---|
| 项目 | 看成员/分析范围、搜索项目、查看本项目提案、创建项目任务 |
| 目录 | 聚焦子树、搜索目录、查看相关依赖（有事实时）、按目录审阅、创建模块任务 |
| 代码文件 | 查看源码/声明、引用与依赖、文件变更、交给 Agent 解释/修改/补测试 |
| 函数/方法 | 看源码/调用方/被调用方/值来源、带同对象进入运行/历史/对照、审阅、补测试/修改任务 |
| 常量等声明 | 定义、引用、所属文件、相关变更、声明调整任务；没有直接运行入口 |
| 文档/普通文件/章节 | 查看全文或章节、内容批注、文件 diff、解释/修改文档任务 |

具体 AI Coding 意图为：解释、找问题、补测试、修改、重构、补文档。选择后预填可编辑的目标和验证预期，不立即修改文件。某动作缺对应能力时说明缺项并提供可用下一步；不能把所有菜单项都接到同一段泛泛提示。

### G. 批注、Agent 与 Review

- 批注绑定节点/版本，可引用源码片段；能保存、继续讨论并带入交接。
- “发给 Agent”先展示目标、意见、解析、代码范围和接收方；用户可增删关联节点。
- 有实际连接时显式发送到已选择的会话；无连接时完整支持保存草稿、复制/导出交接包。复制不显示为已发送。
- 为交接建立持久身份，关联节点、后续讨论与提案。外部 Agent 可通过公开接口读取选定范围、追加结果或提交提案；不得靠访问内部 SQLite 才能完成任务。
- 收到具体提案后，从树节点/讨论点击可定位同一 proposalId 的 diff、真实测试和同输入对照。
- 复用已有验证、应用、撤销和新版本路径。应用后回地图查看新源码；批注、解析、旧观测继续保留其原版本。
- 从节点进入 3D 和返回 2D 时核对同一对象与版本，不能随便挑一个同名函数。

## 开发顺序：M1 → M6

每步先让一条真实用户路径可用，做对应的浏览器检查，然后继续下一步。无需每完成一小步等待用户批准。

| 阶段 | 本阶段交付 | 进入下一步前确认 |
|---|---|---|
| M1 项目地图 | 真实递归树、成员加载、搜索、源码/文档内容、i/… 基础入口 | 打开真实项目自动见根节点，深入至少三层目录到函数，搜索找到未加载成员 |
| M2 多区域工作区 | 独立区域/标签、布局、拖动、管理与恢复 | 同时看根地图和子树/源码；改变一个区域不扰动另一个；刷新与切项目正确 |
| M3 节点知识 | 算法简介、注释、解析编辑/历史、批注/关注 | 不接模型也能写下和保存理解；服务器重启后记录仍在，更新代码后旧记录可识别 |
| M4 节点任务 | 按类型动作、运行/审阅连接、交接/讨论/提案关联、3D 往返 | 一条真实节点批注经外部 Agent 产生实际提案，人能核对并应用/撤销回到地图 |
| M5 按需 LLM | 模型连接、范围预览、显式生成/取消/失败、结果归属 | 一次真实生成（环境允许时）和失败/取消路径；生成不覆盖用户记录 |
| M6 最终交付 | 最新分发包、真实项目旅程、说明与报告 | 仓库外包实际包含本轮代码，两个项目及模型/Agent 资格分别如实记录 |

M4 的复制交接和导入提案是正式可用路径。M5 实现连接与请求能力时，优先复用当前可用适配；没有现成适配就交一个明确可配置的最小适配，不建设通用模型市场。不要从其他软件私自提取凭据，不自动上传真实用户项目。若缺少连接、凭据或用户许可，先用本地测试服务验证协议、取消和失败行为，完成所有独立工作，再把真实调用这一项明确列为“等待外部配置”；不能宣称 M5 完整实测通过。

测试用自己的临时样本。需要真实外部调用时明确使用已获准的接收方和样本范围。外部条件缺失不构成把其他五阶段留空的理由。

## 实现时重点防止的回归

这些是已发生过的产品问题，直接作用于本任务：

- 每次查询/操作携带并核对项目、analysis、entity/内容锚点；服务端也要核对请求身份，不能忽略客户端传来的版本。
- 页面可见项目、运行记录、提案、写入授权目录、重索引目录一致。测试使用两个同名同字节文件的项目，不能靠改文件名规避问题。
- 保存按项目/版本/节点隔离；同名函数不会继承另一项目草稿。重定位后的迁移有依据，不能猜。
- 运行结果显示 record 本身的版本和完整输入，包括 this/globals；树上静态关系不是运行轨迹。
- 请求按区域/标签管理。快速切换、关闭、重开之后，迟到响应不能写入当前的新对象；一个区域失败不让全页白屏。
- 新页面里的运行取消、验证、授权应用/撤销仍走已有真实路径；清理自己的进程，不清理用户的其他服务。

实现方式保持自由：可以拆 app.js、抽组件、调整存储 schema、复用成熟的布局与虚拟化库。只要功能、视觉层次、身份和用户操作契约成立，不需要为了某个文件名或原型内部算法原样复制。原型的硬编码项目、模拟模型和微型布局器不能直接当生产实现。

## 真正需要执行的验收路线

使用真实浏览器点击与输入，保存关键画面，并检查对应 API/记录/磁盘字节。DOM 单元测试和“页面无横向溢出”只能补充，不能代替这些操作。

准备两个临时项目 A/B：包含同路径同名函数、至少三层目录、Markdown、普通文本、缺少语义解析能力的文件；再增加超出成员首批加载量的节点。样本只是验收工具，不扩大为大型仓库性能认证。至少再打开一个实际项目看路径长度和真实布局，性能不足就记录瓶颈并修本条用户路径。

1. 从最终包打开 A，探索页默认是 A 的根地图；逐层展开，文件/函数与实际源码一致。
2. 搜索一个初始未加载的函数，打开并定位祖先；展开过多成员时分页/计数真实。
3. A 的根地图保留在一区，某个目录子树开二区；同一函数的源码与关系分别可见。
4. 区内切多个标签，拖动分隔线、移动标签、最大化/还原、关闭/恢复；源码、选区与输入不串。
5. 点 i，看真实算法摘要与源码注释，定位注释出处；无注释节点有正确空态。
6. 引用两种来源、手动修改、保存解析，修改后保存另一修订；历史及来源可读。
7. 批注一个函数，生成交接草稿；复制内容含正确项目/版本/范围，未发送状态真实。
8. 外部 Agent 只通过公开接口接收/读取任务上下文，提交实际提案或讨论；页面能找到同一交接和 proposalId。脚本指定一个 proposed_by 名称不能算真实 Agent 完整任务。
9. 从函数进入运行，使用不同输入；回地图不丢标签。运行中离页可找到并取消，终态真实。
10. Review 看到真实 diff、测试命令/输出与同输入对照；应用只改 A 的授权文件，B 字节不动。
11. 打开新版本后地图看到更新源码，旧解析标待核对；同项目跨版本撤销可达，磁盘精确恢复。
12. A/B 切换时工作区、同名函数草稿、解析、批注和测试设置隔离；只读打开的项目拒绝写入。
13. 停止旧服务并确认退出，再启动最终包；用真正新加载的页面检查布局、节点与记录恢复。不要只更改同一页面的 token fragment 后当成刷新。
14. 生成 LLM 解释时切到另一个节点，结果回到原节点；取消/失败有真实状态，用户已保存文字不被覆盖。真实提供方未验证时单独记录。
15. 从节点去 3D，点击真实成员返回 2D，断言精确对象和版本；不能仅检查“页面加载成功”。
16. 手动看 1600、1280、窄屏布局：节点标签、i/菜单、弹窗和主按钮清楚可达；图可平移、节点可聚焦，不能靠极小字号塞下一切。

聚焦检查在开发过程中执行。源码定稿后运行适用综合检查并重打包，包后改了源码就重新对齐包和身份：

```sh
node --test web/tests/app.behavior.test.mjs
python3 scripts/verify.py --label explore-map --out evidence/development/<本轮唯一目录>/verify --keep-going
git diff --check
bash scripts/dist.sh
```

沿用项目现有指纹办法核对实际分发包，不把不同构建模式的文件 SHA-256 当作源码指纹。最终包旅程必须在源码定稿后的包上进行。

## 工作节奏与交付内容
