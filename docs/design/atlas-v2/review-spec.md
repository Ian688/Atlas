# 修改审阅与 Agent 交接：实现说明

这两个页面承接用户的真实任务：看懂外部 Agent 的修改，核对证据，决定是否写入。原型中的版本号、提案、时间和运行数字都是示例，不能作为产品运行结果。原型 `review.js` 以 `window.AtlasPages.review/agent` 接入父级 HTML/CSS/JS 壳；无框架迁移要求。产品继续使用现有 Web JS + Rust HTTP + Rust engine + TypeScript worker。

## 修改审阅 / review

桌面内容区采用 228px 提案列表 + 弹性差异区 + 280px 证据列。区域 C1 是版本和入口；C2 是提案；C3 是差异；C4 是验证和对照；C5 是写入行动。长 diff 在中栏阅读，证据始终在近旁；窄窗口先折叠提案列表，验证列移至 diff 后，不能挤压代码为不可读窄列。

| 按钮/控件 | 点击后在哪里出现什么 | 接口/实现 |
|---|---|---|
| C1 粘贴 diff | 模态显示目的、统一 diff 输入；提交成功关闭模态，C2 选中新提案，C3 显示差异 | POST patch/propose；400 在输入下显示具体错误并保留原文；提交中禁重复点击 |
| C1 查看 Agent 交接 | 进入 agent，保留当前提案关联 | 前端路由和 project/analysis/proposal 状态 |
| C2 提案行 | C3/C4/C5 同时切为该提案，保留其他提案尚未结束的验证 | GET patches + patch；不得混用上一个提案的验证/对照 |
| C3 文件差异 / 静态影响 | 中栏局部换内容；影响列实体、调用者和新增未知，明确静态推导 | patch 返回 diff；verification.graph_diff；nodes/reach |
| C3 文件按钮 | 中栏定位该文件 diff；显示路径、增加/删除及新建/删除类型 | 客户端解析合法统一 diff，保留原始行号；多文件不截成一个摘要 |
| C3 完整 diff | 可滚动模态显示完整统一 diff，可选择复制 | 提案已有 diff |
| C3 在关系图查看 | 进入 explore 并选中同一分析的 charge | 选区路由；版本不匹配明确要求切换，不能静默代替 |
| C4 开始/重新验证 | 右栏依次显示隔离副本、重新分析、测试；等待有耗时，终态有具体原因 | POST patch/verify，GET patch/verify?id=；失败可重试；离页保留任务身份 |
| C4 查看输出 | 模态展示 argv、是否运行、退出码、耗时、stdout/stderr、超时或截断标记 | verification.test；ran=false 显示未运行，不能用绿色通过 |
| C4 编辑对照输入 | 模态有 args/this/globals；运行后 C4 左右显示返回/抛错/拒绝/超时 | POST exec-compare，传同份声明输入及 proposal id；先验证；JSON 错误就地提示 |
| C5 检查并应用 | 确认模态展示真实绝对目录、所有路径、基线、测试状态和对照；不在首击写文件 | 从 contract.writes.root 读取，不猜目录；未授权显示启动授权办法 |
| 确认应用 | 显示写入中，成功 C5 改为新版本入口/撤销；失败保留提案并显示路径冲突 | POST patch/apply {id,confirm_path}；检查漂移，不能覆盖其他编辑 |
| 打开新版本 | 进入 explore，使用真实新分析，定位对应实体 | 需要真实新 analysis 能被页面访问；只服务单 analysis 时提供启动/切换流程，不能 URL 标称 v19 而返回 v18 |
| 撤销本次修改 | 模态说明作用文件；二次确认后恢复原字节 | POST patch/revert {id,confirm_path}；漂移拒绝显示具体文件，入口查看当前源码；不提供“强制覆盖”作为默认恢复 |

状态：空列表显示粘贴 diff/去找函数；请求未返回保持结构骨架而非随机假数据；验证失败保留 diff 和上次结果但标过期；未配置测试显示“没有运行测试”，允许产品明确决定是否应用且必须确认知情，不能伪装通过。当前原型默认示范 4 项测试通过，按钮演示模拟异步，工程接入时全部换真实值。应用资格由接口语义决定，不以全部项目测试数量写死。

## Agent 交接 / agent

左侧任务与提案，右侧可核对活动。A1 当前版本/连接；A2 交接目标；A3 同提案摘要；A4 活动；A5 能力说明。

| 按钮/控件 | 点击后在哪里出现什么 | 接口/实现 |
|---|---|---|
| A1 连接说明 | 模态显示回环 URL 和令牌获取办法；显式复制当前连接信息 | 服务会话已有；原型只复制占位模板。令牌不入日志/持久交接文本 |
| A2 目标输入 | 保存在当前项目交接草稿；编辑不跳焦点 | 前端 state + ui-state；不自动发送 |
| A2 查看上下文 | explore 选中同版本目标函数 | 前端路由与实体身份 |
| A2 预览并复制交接文本 | 模态显示当前目标、实体、版本、验收和接口读法，复制后提示交给外部 Agent | 纯本地文本生成；不能显示“Agent 已开始” |
| A2 导出函数上下文 | 模态列范围/未知/截断；点击下载 JSON | POST context；直接导出返回内容，错误保留目标并可重试 |
| A3 审阅这份提案 | review 选中同一个 proposal id，加载同版本事实 | patches/patch + verification + exec-records |
| A3 查看证据引用 | 模态展示基线、派生分析、提案、验证、运行记录的真实 id 与可跳转引用 | 已有记录；无记录显示尚未产生，不猜测 |
| A3/A4 刷新 | 保留当前位置，更新收到的真实结果；错误提示重试 | patches、agent/requests、exec-records；避免把刷新当 Agent 运行 |
| A5 查看可用接口 | 模态显示接口能力及边界 | GET contract；agent/work 是有界动作执行器，不是 LLM 调度 |

Agent 页面不提供伪聊天、模型选择、自动派单或推断进度。已有接口只能证明某会话提交提案以及相关验证；HTTP owner 来自服务会话，CLI proposed_by 是自我声明。UI 标“会话声明/未认证”，不能声称是已认证 Codex 身份。原型活动中的时间为示例；实现按真实记录时间，不能合成完整工具调用时间线。

## 现有能力与需要补的最小数据

已核对 `server.rs`、HOST_API、AGENT_ONBOARDING：patch propose/verify/apply/revert、exec-compare、context、agent requests、ui-state 都已有；启动授权目录和 argv 也已有。先复用这些，不新增同义接口。

为使 A3/A4 可靠归组，需要明确 task/handoff → proposal → verification/run 的关联。若现有记录没有 handoff/task id，先以真实 proposal 为主列，交接草稿单独保存；最小新增字段是可选 handoff_id、source_label（声明来源）、created_at、关联 proposal id 列表。该字段不等于认证身份。完整外部 Agent 会话审计无需作为首版前置。

为使 C5 打开新版本可靠，核实现有单分析服务的真实切换方式；补充版本导航入口或明确重开服务流程。不能发送被静默忽略的 analysis 参数。应用/撤销与版本切换不得仅改前端标题。

## 开发和验收顺序

1. 接入 C2/C3，真实多文件提案选择与差异，不丢提案/版本身份。
2. 接入 C4，验证/测试三态、完整输入对照，覆盖离页后回来。
3. 接入 C5，真实路径确认、应用、漂移拒绝、撤销和新版本入口。
4. 接入 A2 的复制交接/真实上下文导出；接入 A3/A4 同提案证据，不做内置模型。
5. 用真实浏览器完成：外部 Agent 提案 → 页面审阅 → 同输入对照 → 应用 → 新版本 → 撤销；再覆盖无提案、未跑测试、失败、断线、文件漂移。

截图只是版面参考。产品验收按点击结果、真实数据和空错恢复，不能只照图画按钮。所有弹层需 Esc 关闭、焦点进入/返回，长输出可滚动，点击背景关闭不能丢未提交 diff（有改动保留草稿）。异步请求取消/结束后要清理，防旧提案响应覆盖新选区。
