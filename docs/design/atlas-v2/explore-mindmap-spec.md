# 探索代码 · 2D 代码树 / 思维导图 与多展示区

本稿配套可点样例 `explore-mindmap.html`（`explore-mindmap.js`，复用 `style.css`）。
样例不接真实接口、不执行目标代码，所有项目、函数、解释与对话都是交互样例；它不证明任何分析、
运行、写入或模型调用已经发生。正式实现仍是 vanilla JS/CSS + SVG/DOM，不更换前端框架。

## 0 这一稿改什么

现状（`explore-spec.md` E1–E4）：探索页 = 搜索 + 一跳关系 + 源码 + 值来源 + 未知，主内容是"一个当前对象"。

本稿把**项目结构本身**提为该页的第一入口，并引入三件东西：

1. **导航区 + 展示区**的工作区模型：树/导图负责找，展示区负责读；展示区可以有多个。
2. **节点级 `i` / `…`**：每个节点自带"简介"与"该节点的动作"，动作按节点类型不同。
3. **解析记录**：把"Atlas 算法简介 / 代码注释 / LLM 解释"三种来源**分开呈现、可引用、可编辑**，
   用户保存后成为这条分析上的一条**解析记录**（Atlas 对该代码的解析），带作者、时间与版本。

不变量（沿用仓库既有边界，写死在交互里而不是靠承诺）：

- 静态分析、执行观测、修改提案、模型推测**四类内容可分辨**，永不混写成一种。
- 未解析、未知、未分析、被撤下**如实显示**；`未展开` 与 `按预算不绘制` 是两句不同的话。
- 批注是 Intent，不是代码；写入源码仍走既有授权路径（`--allow-writes` + 可写方式打开）。
- 模型输出永远不作为执行证据，也不自动进入解析记录（要用户点保存）。

## 1 页面分工

| 区域 | 职责 | 不做什么 |
|---|---|---|
| 导航区（左，可拖宽 280–560px） | 2D **代码树** / **思维导图** 两个投影，找节点、看结构、看计数与未知 | 不显示源码正文；不做执行 |
| 展示区（右） | 1–4 个 **pane**，每个 pane 一行 **tab**；tab 承载一个节点的一种视图 | pane 之间不共享滚动位置；不隐式改选区 |
| 展示区头部 | 新建展示区、布局档（单/左右/2×2）、全部收起 | 不改变导航区筛选 |
| 状态栏（共享壳） | 当前对象、当前版本、三类内容的图例入口 | 不用动画表示执行状态 |

## 2 工作区与 pane 管理

| 标识 | 用户看到什么 | 点击 / 输入 → 出现什么 | 数据与状态 | 对应实现 |
|---|---|---|---|---|
| W1 新建展示区 | 展示区右上「＋ 新建展示区」；树节点 `…` 里的「在新展示区域打开此节点」 | 新增一个 pane 并打开该节点；布局档自动从单栏变左右双栏 | 上限 4 pane；第 5 次给明确拒绝（不静默丢弃）；空 pane 显示"从左侧选一个节点，或用 `…` 在新区打开" | 新增页面状态；`/api/ui-state` 按 `analysis_id + project` 保存布局 |
| W2 pane 头部 | tab 行（每 tab：类型图标 + 名称 + 关闭）＋ 最小/最大化/关闭 | 点 tab 切视图；中键或 `×` 关闭 tab；拖拽重排 | 关掉最后一个 tab 的 pane 自动关闭；当前 tab 写入 ui-state | 纯前端 |
| W3 布局档 | 单栏 / 左右 / 2×2 | 切换档位保留每个 pane 的 tab 与内容 | 窄屏（<1100px）强制单栏，并说明为什么 | 复用 v2 断点策略 |
| W4 恢复 | 重开页面后回到同样的 pane/tab 组合 | 切项目、重启服务后按 `analysis_id` 恢复；节点不在该分析里 → 该 tab 显示"此节点不在当前版本"，可 relocate | 不与别的项目串；版本不一致必须显示而不是静默替换 | `/api/ui-state`、`/api/relocate` |

## 3 导航区：树与思维导图

层级与计数**复用 `web/hierarchy.js`**（2D/3D 已共用的唯一定义）：项目 → 目录（顶层目录）→ 文件 → 函数。
第四层不是"语句"：函数内部的值来源/数据流只在展示区展开，否则节点数会爆炸且不可读。

| 标识 | 用户看到什么 | 点击 / 输入 → 出现什么 | 数据与状态 | 对应实现 |
|---|---|---|---|---|
| N1 树 / 导图切换 | 顶部「树」「导图」两个按钮 | 切换投影，**当前节点与展开状态保留** | 两个投影共享 hierarchy；导图以当前节点为中心，向内（所属目录/文件）与向外（调用、被调用）分层 | 复用 hierarchy.js；导图布局用已有 `layout.js` |
| N2 节点行 | 类型图标、名称、真实计数 chip（文件数/函数数/未解析/未分析） | 单击＝**选中**（高亮，不打开）；双击或 Enter＝在**当前 pane** 打开 | 选中 ≠ 打开：可同时选中一个、打开多个 | W 系列同上 |
| N3 展开 | 目录/文件左侧三角；默认展开项目 + 目录 | 展开文件 → 拉取该文件函数成员（分页）；折叠保留计数 | 未加载 = "还有 N 个成员未加载"；本层不绘制 = "本层只计数，不列出成员"；两者文案不同 | 成员来自 `/api/nodes` 分页；大项目需要按目录/文件分页的新查询（现状是全局节点分页） |
| N4 节点上的 `i` / `…` | 行右侧两个按钮（hover/聚焦出现，键盘可达） | `i` → 打开简介 tab；`…` → 打开动作菜单 | 菜单项按节点类型不同，每项带性质 chip | §4、§5 |
| N5 覆盖与核对 | 项目节点展开后第一块：captured/ignored/unreadable/被撤下 的真实计数；以及 `项目合计 == Σ目录 == Σ文件` 的核对结果 | 点任一条 → 过滤树到对应文件；不一致时**红字说明哪一项对不上** | 用 `atlasLevelInvariants` 的结果，不自己再算一套 | hierarchy.js 已有，页面只需显示 |
| N6 只看关注 / 搜索 | 「只看关注」开关；搜索框 | 过滤树；搜索命中直接定位并选中（不改变已打开的 tab） | 关注集合按分析保存；搜索沿用 `/api/search` 的有界分页 | `/api/search`、`/api/ui-state` |
| N7 未知与未分析标记 | 行内小标记：`未解析 N` / `诊断 N` / `被撤下` | 点标记 → 未知镜头或说明弹层 | 未知数量来自 flow 与分析诊断，不估算 | `/api/flow`、`/api/report` |

## 4 节点动作矩阵

性质 chip 四类：`只读事实`（引擎已发布的事实）、`本地执行`（真的启动进程）、`写入`（改你的文件，需授权）、
`模型`（模型输出，是推测）。

### 4.1 通用（所有节点）

| 动作 | 性质 | 说明 |
|---|---|---|
| 在新展示区域打开此节点 | 只读事实 | 新增 pane 并打开；已有同样 tab 时聚焦而不是重复 |
| 在简介面板查看 / 生成 | 只读事实 + 模型 | 见 §5 |
| 批注此节点 | 只读事实（写入的是 Atlas 记录，不是源码） | 见 §6 |
| 复制固定上下文 JSON | 只读事实 | 复用 `/api/context`：analysis + entity + 版本 |
| 复制路径 / 名称 / 实体 id | 只读事实 | —— |
| 加入 / 移出关注 | 只读事实 | 关注集合可过滤树、可批量导出 |
| 在 3D 地图中定位 | 只读事实 | 复用 `/city3d` 与共享选区 |
| 查看该节点的解析记录与批注 | 只读事实 | 已保存的记录、谁在哪个版本写的 |

### 4.2 按类型

| 类型 | 动作 | 性质 | 空态 / 失败要说的话 |
|---|---|---|---|
| 项目 | 重新分析（有界、可取消）、对比两个版本、项目设置（测试命令/超时）、任务队列、导出项目上下文、**本次覆盖说明**（多少文件被解析/跳过/被撤下/未分析） | 只读事实 / 本地执行 | 分析中显示进度与取消；失败给出服务端的原始原因，不吞掉 |
| 目录 | 只看这个目录、设为工作集、目录统计（文件/函数/未知/未解析）、批量导出上下文、在 3D 定位 | 只读事实 | 目录为空 → "这个目录没有被捕获的文件" |
| 文件 | 打开源码（带锚点）、函数成员清单、文件级调用关系、诊断清单、复制相对路径、**声明不参与分析**（写入项目声明，不是偷偷忽略） | 只读事实 / 写入（声明） | 文件被忽略或读不到 → 明确 disposition，不给空源码 |
| 函数 | 理解（值来源 / 未知）、**受控运行**（需声明输入）、看调用者 / 被调用者（一跳，可继续）、查看它在哪些版本里变过、生成修改提案（Intent）、对比两个版本的该函数、导出函数上下文、运行历史 | 只读事实 / 本地执行 / 写入 | 没有值来源 → "当前分析未给出"；执行被拒 → 保留拒绝原因与未启动的证据 |
| 常量 / 类 | 引用处、被读写的位置（若分析给出）、作为上下文交给 Agent | 只读事实 | 分析未建模 → 直说 |

## 5 `i` 简介面板

三个来源**分栏呈现，永不混写**，各自带来源标签：

| 分栏 | 内容 | 生成方式 | 证据等级 |
|---|---|---|---|
| Atlas 算法简介 | 签名、参数、返回、被谁调用、值来源摘要、未知项、诊断计数 | 引擎已发布事实，打开即读 | 静态分析 |
| 代码注释 | 源码里已有的注释/文档字符串，**原样引用**并带字节锚点 | 从源码抽取 | 源码事实 |
| LLM 解释 | 自然语言解释 | **用户再次选择生成**（按钮触发）；生成中/失败/重试都有状态 | 模型推测（永不作为执行证据） |

编辑与保存：

1. 每一栏可以「引用到解析」把内容带进下面的编辑区（引用保留来源标记，不假装是自己写的）。
2. 用户手动编辑后点「保存为解析记录」→ 写入一条绑定 `analysis_id + entity_id + 版本` 的记录，
   带作者与时间；页面显示"这是谁在哪个版本写的、基于哪些来源"。
3. 可以「另存为新版本」，历史记录可并排对比；删改历史要留痕，不静默覆盖。
4. 保存的是**Atlas 对该代码的解析**（Intent/记录），不是源码，也不进入执行或修改提案的证据链。

## 6 `…` 菜单与批注 → Agent

- 菜单首三项固定：`在新展示区域打开` · `批注` · `复制固定上下文`；其后按节点类型分组（§4.2）。
- 「批注」= 对这个节点写下意见（Intent）。批注界面提供「发给 LLM Agent」：把**批注 + 固定上下文**
  交给 Agent 会话，用户与 Agent 就此节点往复沟通；Agent 的建议回到页面仍只是**提案**，
  要变成源码必须走 `/api/patch/propose` → 验证 → 用户确认应用。
- 批注与解析记录都不改源码；两者都在 UI 上标为"记录"，与"源码变更提案"分开显示。

## 7 状态与边界

每个 pane 独立状态机：`未选择 · 加载中 · 有数据 · 空 · 错误 · 部分(截断) · 版本不符`。
一个 pane 失败**不白屏**其他 pane；迟到的响应不覆盖新选择（沿用现有 generation guard 做法）。
窄屏与键盘：树内 ↑↓ 移动、→ 展开、← 折叠、Enter 在当前 pane 打开、`i` 简介、`m` 菜单；
所有 `i` / `…` 都是真正的按钮，有 `aria-label`。

## 8 与现有实现的对应

| 设计项 | 现状 | 需要新增 |
|---|---|---|
| 树的层级与计数 | `web/hierarchy.js` 已有（含合计核对、`omitted` 与 `budget` 的区分） | 页面把核对结果画出来 |
| 成员与结构查询 | `/api/nodes`（全局分页）、`/api/search`、`/api/edges`、`/api/reach` | **按目录/文件分页**的成员查询，否则大项目首屏拉不动 |
| 简介三来源 | `/api/flow`、`/api/source`（注释在源码里）、无模型调用 | 解析记录的读写（可作为 annotation 的一个 kind）；模型生成入口（本机操作者触发） |
| 批注与 Agent | `/api/annotation`、`/api/annotations`、`/api/agent/request`、`/api/agent/work` | 批注 → Agent 会话的页面串接 |
| 运行 / 提案 / 应用 | `/api/exec`、`/api/exec-compare`、`/api/exec-records`、`/api/profile`、`/api/patch/*` | 在节点菜单里按类型暴露（已有接口，缺入口） |
| 布局与选区持久化 | `/api/ui-state`、`/api/selection`、`/api/relocate` | pane/tab 组合的存取 |
| 3D 定位 | `/city3d` 真实 WebGL2 + 共享选区 | 从节点菜单直达 |

## 9 验收（照这条路线点一遍）

1. 打开项目 → 探索页默认落在**思维导图**，根节点是项目名。
2. 展开 项目 → 目录 → 文件 → 函数；每层计数与项目合计一致，改动数据后不一致要**可见地红**。
3. 选中一个函数 → Enter 在当前 pane 打开；再点另一个文件的 `…` → 「在新展示区域打开此节点」→ **多出一个 pane**。
4. 点 `i` → 三来源分栏；点「生成 LLM 解释」→ 有生成态、结果标为模型推测；引用进编辑区 → 保存 → 出现带作者与版本的解析记录。
5. 点 `…` → 批注 → 发给 Agent → Agent 会话里带着同一上下文；Agent 的改动**不会**直接写文件。
6. 关掉 pane / 切布局档 / 刷新页面 → 组合与 tab 恢复；切到另一个项目 → 不串。
7. 一个 pane 故意加载失败 → 只有该 pane 报错并给下一步，其他 pane 照常。

## 10 不做与不做假的

- 不换前端框架；不把样例业务描述当成生产事实。
- 不在本稿接真实接口、不执行任何目标代码、不调用模型。
- 不把"未展开"写成"没有"；不把"按预算不绘制"混进"omitted"。
- 不用动画或模型输出当执行证据；不把解析记录写成源码变更。
